# 휴가낼게요! — 발표용 개선 정리 (데이터 파이프라인 · 평가)

교수님 발표 팁 순서(문제 정의 → 차별성 → 개선 수치 → 기대 효과 → 한계)에 맞춰,
지금까지 한 평가·개선 작업을 슬라이드에 바로 옮길 수 있게 정리했다.
**수치는 모두 실제로 돌린 결과**이고, **[가정]** 표시는 실측이 아닌 예시 계산이다.

---

## 1. 문제 정의 (1분)

- **누가**: B2B 고객사(예: 스칼라테크)의 직원과 인사담당자
- **불편**
  - 직원: "배우자 출산휴가 며칠?", "출장 숙박비 한도?" 같은 질문의 답이 **규정집 5종(취업·복리후생·근태·휴가·출장), 조문 86개** 안에 흩어져 있어 직접 찾기 어렵다.
  - 인사담당자: 같은 질문을 반복해서 응대하고, 잘못 답하면 노무 리스크가 생긴다.
- **목표**: 직원이 말(음성)로 물으면 **규정 조문을 근거로** 답하고, 규정에 없는 질문은 **지어내지 않고 담당자에게 넘긴다**.

---

## 2. 차별성 (아키텍처 슬라이드에 함께)

| 일반 챗봇 / 사내 검색 | 휴가낼게요! |
| --- | --- |
| 답만 주고 출처가 없거나 문서 단위 | **규정명 · 조문 · 쪽**까지 출처 표시 (예: 휴가규정 제12조, 4쪽) |
| 문서에 없으면 그럴듯하게 지어냄 | 근거가 없으면 `handoff`로 **인사담당자 연결** |
| 키워드가 정확해야 검색됨 | "월급", "출산휴가" 같은 **일상어로 물어도** 규정 용어 조문을 찾음 (관련어 사전) |
| 품질을 감으로 판단 | **평가셋 44문항 + 지표(Hit@K, MRR)**로 숫자로 관리, 바꿀 때마다 재측정 |
| 텍스트 입력 | **음성 질문 → 음성 답변** (현장·이동 중 직원) |

## 3. 평가 방법 (결과 슬라이드 앞에 짧게)

- **평가셋** `data/eval/eval_set.csv`: 32문항 = 일반 28 + 문서에 없는 예외 4
  - 유형: 사실 17 · 조건(계산·판단) 6 · 절차 3 · 조문번호 1 · 함정 1 · 예외 4
  - 각 문항에 기대답변, 근거 규정·조문·쪽을 적고, 기대답변의 숫자가 근거 조문에 실제로 있는지 코드로 검증
- **튜닝에 안 쓴 확인용 질문** `holdout_set.csv`: 12문항 (평가셋에만 맞춘 효과인지 확인)
- **지표** (검색 단계)
  - **Hit@K**: 정답 조문이 상위 K개 안에 있는 비율
  - **MRR**: 정답 조문 순위의 역수 평균 (1위면 1점, 2위면 0.5점 …)
- **규칙**: 한 번에 하나만 바꾸고, 같은 평가셋으로 다시 잰다.

## 4. 실패 현상별 개선 전후 (핵심 슬라이드)

교재 개선 루프 표의 5가지 실패 현상 기준.
**개선 전** = 임베딩 ada-002, 관련어 없음 / **개선 후** = 임베딩 3-large + 관련어 사전 (청킹은 둘 다 500자 고정)

### ① 관련 문서가 검색되지 않음 → 조치: 임베딩 모델 교체

| 지표 (평가셋 28문항) | 개선 전 | 개선 후 |
| --- | --- | --- |
| Hit@1 | 0.714 (20/28) | **0.786 (22/28)** |
| Hit@3 | 0.821 | **0.857** |
| Hit@5 | 0.893 (25/28) | **0.929 (26/28)** |
| MRR | 0.778 | **0.833** |

검색 예시 (정답 조문의 순위)
| 질문 | 개선 전 | 개선 후 |
| --- | --- | --- |
| 출산휴가는 얼마나 쓸 수 있어? | 5위 밖 (1위: 출장규정 제6조) | 4위 |
| 노동절에도 쉬어? | 5위 밖 (1위: 출장규정 제6조) | 찾음 |

> 발표 한 줄: **"MRR 0.778 → 0.833, 정답을 1위로 찾는 질문 20 → 22개"**

### ④ 질문 표현이 바뀌면 답이 달라짐 → 조치: 동의어(관련어) 사전

(이 표는 임베딩 3-large로 고정하고 관련어만 켜고 끈 비교)

조문 제목에 직원이 쓰는 말을 붙였다. 예: `제2조 근무일과 소정근로시간 (관련어: 점심시간, 쉬는 시간, 출근 시간)`

| 질문 | 관련어 전 | 관련어 후 |
| --- | --- | --- |
| 출퇴근 시간이랑 점심시간이 어떻게 돼? | 3위 | **1위** |
| 수습기간에는 월급이 깎여? | 5위 밖 | 4위 |

**튜닝에 안 쓴 새 질문 12개**로 확인 (평가셋 과적합 아님을 보이기 위해)
| 지표 | 관련어 전 | 관련어 후 |
| --- | --- | --- |
| Hit@1 | 0.583 (7/12) | **0.667 (8/12)** |
| MRR | 0.715 | **0.767** |

### ③ 문서에 없는 내용을 지어냄 (환각) → 조치: 근거 평가 후 handoff (RAG 워크플로)

| 질문 (규정에 없음) | 실제 답변 |
| --- | --- |
| 출퇴근할 때 회사 주차비 지원돼? | "제공된 문서에서 답변에 사용할 근거를 찾지 못했습니다." → `handoff: true` |
| 형제가 결혼하면 경조휴가 받아? | "형제 결혼에 대한 경조휴가 규정은 명시되어 있지 않습니다. 경조휴가는 본인 혼인, … 형제자매 사망에 대해서만 규정" (지어내지 않음) |

- 포인트: 검색은 항상 "가장 비슷한" 조문을 돌려준다. 예외 질문의 검색 거리(0.24~0.41)가 정답 질문(0.20~0.40)과 같은 범위라 **거리만으로는 못 거른다** → LLM이 근거를 평가해서 거르는 구조가 필요했다.
- 주의: 같은 질문도 실행마다 `no_evidence`(handoff) / `answered`(없다고 답함)로 갈린다. 둘 다 지어내지는 않았다.

### ② 출처는 맞는데 답이 엉뚱함 → 남은 과제

| 질문 | 실제 답변 | 원인 |
| --- | --- | --- |
| 식대는 한 달에 얼마야? | "어떤 회사나 조직의 식대 정책에 대해 묻고 계신가요?" (되묻기) | 회사명이 없는 짧은 질문을 모호하다고 판단 |
| 스칼라테크 식대는 한 달에 얼마야? | "월 식대 지원 금액은 200,000원입니다" (복리후생규정 제6조) | 회사명을 넣으면 정상 |

- 조치(다음): RAG 프롬프트에 "모든 질문은 스칼라테크 사내 규정에 대한 것"이라는 전제를 넣는다. (RAG 담당에 전달)

### ⑤ 답은 맞는데 출처가 비어 있음 → 조치: 청크 메타데이터 (해결)

모든 청크에 규정명·문서번호·장·조문·제목·쪽을 붙여 적재했다. 실제 응답 예:
```json
{"answer": "배우자 출산휴가는 유급 20일입니다.",
 "sources": [{"doc": "스칼라테크 휴가규정", "article": "제12조", "page": 4}]}
```

## 5. 실험 기록 — "하나씩 바꾸고 다시 쟀다" (부록 또는 결과 슬라이드 하단)

| # | 바꾼 것 | 결과 (평가셋 MRR) | 판단 |
| --- | --- | --- | --- |
| 0 | 기준: 고정 500자 + ada-002 | 0.778 | — |
| 1 | 청킹 고정 → **조문 단위** | 0.698 | ✗ 오히려 하락. 긴 조문이 한 벡터로 뭉개짐 |
| 2 | 임베딩 → **3-small** | 0.736 | ✗ 하락 |
| 3 | 임베딩 → **3-large** | 0.823 | ✓ 채택 |
| 4 | 3-large + **관련어 사전** | **0.833** | ✓ 채택 (새 질문 12개에서도 0.715 → 0.767) |

> 발표 포인트: **"조문 단위가 당연히 좋을 줄 알았는데, 재 보니 아니었다."** 감이 아니라 수치로 결정했다는 근거.

### 왜 청킹은 500자 고정을 유지했나

규정집은 조문 구조가 뚜렷해서 "조문 하나 = 청크 하나"(조문 단위)가 더 좋을 거라고 예상했다. 같은 평가셋으로 두 방식을 비교했다.

**1) 임베딩 모델을 바꿔도 1위 적중과 MRR은 매번 고정 500자가 높았다**

| 임베딩 | 청킹 | Hit@1 | Hit@3 | Hit@5 | MRR |
| --- | --- | --- | --- | --- | --- |
| ada-002 | **고정 500자** | **0.714** | **0.821** | 0.893 | **0.778** |
| ada-002 | 조문 단위 | 0.571 | 0.786 | 0.893 | 0.698 |
| 3-small | **고정 500자** | **0.679** | **0.786** | **0.857** | **0.736** |
| 3-small | 조문 단위 | 0.536 | 0.714 | 0.786 | 0.627 |
| 3-large | **고정 500자** | **0.786** | 0.857 | 0.893 | **0.823** |
| 3-large | 조문 단위 | 0.714 | 0.857 | **0.964** | 0.799 |
| 3-large + 관련어 | **고정 500자** | **0.786** | 0.857 | 0.929 | **0.833** |
| 3-large + 관련어 | 조문 단위 | 0.643 | **0.893** | 0.929 | 0.759 |

조문 단위가 앞선 건 "3-large에서 5위 안에 드는 비율(0.964)" 하나뿐이고, 관련어를 붙이면 그마저 같아졌다.

**2) 문항별로 보면 (ada-002, `result.csv`)**: 5위 안 적중은 둘 다 25/28로 같지만, 정답 순위가 달라진 8문항 중 조문 단위가 나은 건 2문항, 나쁜 건 6문항이었다.

| 질문 | 고정 500자 | 조문 단위 |
| --- | --- | --- |
| 식대는 한 달에 얼마야? | 5위 | **1위** |
| 출퇴근 시간이랑 점심시간이 어떻게 돼? | 3위 | **2위** |
| 배우자가 출산하면 휴가를 며칠 받을 수 있어? | **1위** | 2위 |
| 일주일에 최대 몇 시간까지 일할 수 있어? | **1위** | 4위 |
| 월급은 언제 들어와? | **2위** | 3위 |
| 정년이 몇 살이야? | **1위** | 2위 |
| 수습기간에는 월급이 깎여? | **1위** | 5위 |
| 복지포인트는 얼마나 줘? | **1위** | 2위 |

**3) 원인 (추정)**: 조문 하나에 여러 주제가 들어 있으면 벡터 하나로 뭉개진다.
- 예: "수습 월급" 정답인 취업규정 제5조는 근로계약 명시사항·기간제 명시사항·수습·수습 종료·기간제 전환 다섯 항이 한 조문이다. 조문 단위로는 "수습" 주제가 묻혀 5위로 밀렸다.
- 예: "주 최대 근로시간" 정답인 근태규정 제9조도 신청 절차·한도·긴급근로·단시간근로자 등 여섯 항이다.
- 고정 500자는 이런 조문을 2~3조각으로 나눠서, 질문과 맞는 항이 있는 조각이 따로 검색된다.

**4) 왜 1위·MRR을 기준으로 골랐나**: 음성 서버는 상위 4개 문서만 LLM에 넘긴다. 정답이 1~2위에 있어야 답변에 확실히 쓰이므로, "5위 안에 있다"보다 **"앞 순위에 있다"(Hit@1, MRR)**가 서비스 품질에 직접 영향을 준다.

> 발표 한 줄: **"조문 단위는 5위 안 적중만 비슷하고, 1위 적중·MRR은 모든 조건에서 고정 500자가 높았다 → 500자 고정 유지"**

## 6. 기대 효과 (B2B)

정량 수치는 고객사 데이터가 없어 **[가정]** 으로 계산식을 제시한다. 발표 때 가정임을 밝히고 쓴다.

**[가정] 인사 문의 응대 시간 절감**
- 직원 300명, 1인당 월 1건 규정 문의, 담당자 응대 1건 10분
- → 월 300건 × 10분 = **월 50시간**
- 평가셋 기준 정답 조문을 상위 5개 안에 찾는 비율 **92.9%** → 이 중 상당 부분을 자동 응답으로 대체 가능
- 문서에 없는 질문만 담당자에게 넘어가므로, 담당자는 **판단이 필요한 문의에 집중**

**정성 효과**
- 직원: 근무시간 외·이동 중에도 음성으로 즉시 확인
- 회사: 조문 근거가 함께 나가서 **잘못된 안내로 인한 노무 리스크 감소**, 규정 개정 시 PDF만 다시 적재하면 반영
