# RAG 서비스 개선 전후 비교

- 작업일: 2026-10-26 (Asia/Seoul)
- 코드 대상: `rag-code-template_ext/rag-service/` 이하
- 기준 커밋: `861a767cb9fd224474b80147038faed4a5c39d0f`
- 결론: 조문 검색·근거 제한·인용·유보 상태를 개선했고, 실제 평가에서 정상 질문 응답이 늘었다. 다만 검증 단계의 지연과 과도한 유보가 남았으며, 전체 문항을 해결한 결과는 아니다.

## 1. 비교 방법

### 비교를 위해 고정한 조건

| 항목 | 조건 |
|---|---|
| 실제 평가 질문 | `data/eval/eval_set.csv`, 일반 28 + 예외 4 = 32문항 |
| 경로 | `RagService.ainvoke()`의 실제 세션 경로 |
| 모델 | `gpt-4o`, temperature 0, 출력 상한 1,200토큰 |
| 임베딩 | `text-embedding-ada-002` |
| 인덱스 | 기존 `faiss_db/pdf`, 전후 SHA-256 동일·각 실행 중 변경 없음 |
| 검색 | 일반 의미 검색 top_k=5, 최대 재검색 1회 |
| 실행 | 동시성 2, 질문마다 새 세션, 전체 제한 60초 |
| 예산 | 호출당 입력 6,000 / 전체 입력 24,000토큰 |
| 차이 | 생성 후 검증을 추가해 기본 모델 호출 한도는 8 → 9 |

실제 질문과 검색된 규정 내용의 OpenAI API 전송은 사용자에게 명시적으로 승인받았다. 서비스 서버의 설정이나 데이터 파이프라인 코드는 수정하지 않았다. 임베딩 교체도 하지 않았다.

개선 전 코드는 별도 스냅샷으로 고정한 뒤 평가했다. 개선 전후의 인덱스·질문·모델·k 동일 여부를 비교 스크립트에서 검사했으며, 최종 코드의 모듈 해시는 `final_live/manifest.json`과 일치한다.

### 구분한 테스트

1. **기존 자동 테스트**: 서비스의 모의 모델·로컬 저장소 테스트. 네트워크 모델의 답변 정확도를 뜻하지 않는다.
2. **고정 회귀 시나리오 8개**: 같은 모의 모델 출력과 FAISS 사례로 전후 계약을 비교한다.
3. **실제 API 32문항**: 실제 임베딩과 LLM 호출 결과다. 상태·토큰·지연은 자동 집계한다.
4. **핵심 답변 검토**: 기대값과 실제 답변을 Codex 에이전트가 1차 검토했다. 독립적인 사람의 평가나 법률 검증이 아니다.

이번 32문항은 개선 중 결과를 확인하고 프롬프트에 반영한 **개발셋**이다. 개선 전달 문서가 언급한 `holdout_set.csv`는 현재 작업 트리에 없어 실행하지 못했다. 새 질문으로의 일반화 성능을 입증한 결과로 볼 수 없다.

## 2. 코드 변경

| 파일 | 변경 |
|---|---|
| `rag_retrieval.py` 신규 | 조문 지정 질문을 파싱하고 FAISS docstore 메타데이터로 정확 조회. 매핑은 서비스 스냅샷당 1회 구축 |
| `rag_workflow.py` | 평가에서 선택한 출처만 생성에 전달, 구조화 답변·유보, 생성 후 근거 검증, 명시 조항의 무관한 재검색 방지 |
| `rag_state.py` | `GenerationDecision`, `AnswerReview`, 검색 제약/선택 근거 State 추가. 호출 예산 9로 조정 |
| `rag_agent.py` | 사실 답변에 유효한 인용 필수, 대상·조건·예외 확대 금지 지침 |
| `rag_router.py` | 회사명이 없다는 이유로 독립적인 문서 질문을 과도하게 확인 질문으로 돌리지 않도록 지침 보완 |
| 테스트 | 기존 모의 모델을 구조화 생성·검증 인터페이스에 맞추고 회귀 검증 13개 추가 |
| 평가 도구·README | 실제/모의 실행 기록, 조건 검사와 비교 집계 도구, 실행 안내 추가 |

선택 근거의 ID는 생성 전에 `S1..Sn`으로 다시 부여한다. 완료 턴의 출처 순서와 일치시켜, 두 번째 검색 후보만 선택된 경우에도 최초 응답과 재전송의 인용이 어긋나지 않게 했다.

조문 지정 검색은 유사도 상위 후보를 먼저 고르는 FAISS filter 방식 대신 전체 docstore의 메타데이터 매핑을 사용한다. 따라서 의미 검색에서 26위인 조문도 정확 조회할 수 있다. 규정명 없는 조항이 여러 규정에 존재하면 확인 질문을 반환하고, 없는 조항은 다른 조항으로 대체하지 않는다.

일반 의미 검색의 기본 k는 이미 5여서 유지했다. 음성 서버의 k 수정 및 임베딩 모델 교체는 코드 범위 밖이다. 이번 실험은 k=4/5 성능 비교가 아니다.

## 3. 자동 테스트와 고정 회귀 결과

| 항목 | 개선 전 | 최종 개선 후 |
|---|---:|---:|
| 서비스 자동 테스트 | 94/94 통과 | 107/107 통과 |
| 동일 고정 회귀 시나리오 | 1/8 통과 | 8/8 통과 |

자동 테스트 개수 증가 자체를 품질 향상률로 해석하면 안 된다. 기존 검증을 유지하면서 새 실패 사례를 추가한 결과다. 기존 테스트 중 구조화 출력용 모의 인터페이스, 검증 호출 수 기대값, 요약 예산 소진 경계값은 새 호출 단계에 맞게 조정했다. 요약 실패 시 완료 답변 보존 등의 기존 의미적 검증은 유지했다.

| 고정 사례 | 개선 전 관측 | 최종 관측 |
|---|---|---|
| 정상 인용 답변 | answered | answered 유지 |
| 평가에서 선택하지 않은 출처 인용 | answered로 허용 | generation_error로 거부 |
| 인용 없는 사실 답변 | answered로 허용 | generation_error로 거부 |
| 생성 단계의 유보 | answered로 저장 | no_evidence로 저장 |
| 두 번째 출처만 선택 | 전체 출처 반환 | 선택 출처만 전달·반환 |
| 유사도 26위의 명시 조항 | 다른 규정 검색 | 지정 규정·조항 정확 조회 |
| 없는 조항 요청 | 무관한 문서로 답변 | no_evidence |
| 규정명 없는 중복 조항 | 임의 답변 | clarification_needed |

추가 회귀 검증은 생성 컨텍스트에서 미선택 자료 제거, 선택 출처 재번호화 후 재전송 일치, 표현이 다른 구조화 유보 저장, 생성 후 검증 거부·예산 소진, 메타데이터 매핑 재사용, 잘못된 인용 차단 등을 포함한다.

중앙값 지연은 약 22.3%, 모델 호출 수는 약 28.9% 늘었다. 입력 토큰은 약 11.2%, 출력 토큰은 약 22.0% 늘었다. 실제 금액은 계산하지 않았다. 실행이 별도 시점이고 모델 응답 변동이 있으므로 지연 차이를 모두 코드 효과로 단정할 수 없다.

### 에이전트의 핵심 답변 검토

| 지표 | 개선 전 | 최종 개선 후 |
|---|---:|---:|
| 일반 질문의 핵심 답변 일치 | 23/28 (82.1%) | 26/28 (92.9%) |

위 수치는 기대답변과 실제 답변에서 질문의 핵심 사실·수치·명시적 조건을 비교한 **에이전트 1차 검토**다. 모든 부가 조건을 빠짐없이 설명했는지 평가한 완전성 점수가 아니며, 독립적인 사람의 정확도 채점도 아니다. 예를 들어 '며칠인가'에 일수만 올바르게 답했으면 기간·분할 규칙을 모두 덧붙이지 않아도 핵심 답변은 일치로 보았다. 문항별 판정과 한계는 별도 `agent_review.json`에 남겼다.

### 개선된 주요 사례

- **Q03 식대**: 특정 회사나 기관을 다시 묻던 응답이 월 200,000원 답변으로 바뀌었다.
- **Q08 근무·점심시간**: 불필요한 회사 확인 질문에서 실제 시간 안내로 바뀌었다.
- **Q23 정년**: 회사·국가를 다시 묻던 응답이 만 60세 도달 연도의 12월 31일 안내로 바뀌었다.
- **Q27 휴가규정 제12조**: 개선 전에는 요청 조문을 확인할 수 없다며 취업규정 제12조를 대신 설명했다. 최종은 배우자 출산전후휴가 조문과 유급 20일·사용기간·분할 조건을 정확히 제시했다.
- **Q06 5년 근속 연차**: 전후 모두 17일로 답했다. 추가 검증이 계산 가능한 질문을 무조건 차단하지는 않았다.
- **Q29~32 예외 질문**: 최종은 모두 no_evidence로 유보했다. 이 네 사례는 개선 전에도 유보했으므로 실제 예외 대응률이 증가했다고 주장하지 않는다.

### 남은 실패 및 회귀

| 사례 | 최종 결과 | 의미와 다음 과제 |
|---|---|---|
| Q10 주 최대 근로시간 | 생성 후 검증에서 no_evidence | 개선 전의 52시간 핵심 답변을 최종 결과에서 잃었다. 선택 근거·실제 인용·검증 판정을 함께 확인해 과도한 유보를 줄여야 한다 |
| Q28 복지포인트 | no_evidence | 명시적 부정 규정인 '새로 두지 않음'을 답해야 하나 아직 실패한다. 검색된 문서에 없는 사실과 문서에 명시된 부정 답변을 더 잘 구분해야 한다 |

생성 후 검증도 같은 계열 모델을 사용하므로 독립적인 정답 판정기가 아니다. 유효한 인용이 있다는 것만으로 의미적 근거 일치를 보장하지 않으며, 검증기의 과도한 거절도 현재 확인된 위험이다. 원인 분석을 위해서는 생성 초안·선택 근거와 검토 사유를 연결한 별도 진단 자료를 추가하는 것이 유용하다.

## 5. 중간 실험도 보존

`after_live/`는 생성 후 검증을 넣기 전의 첫 개선안이다. 여기서 Q01에 '3회 나누어 사용'과 '최대 4개 사용구간'을 혼동하는 부가 설명이 관측됐고, Q32의 '규정에 명시되지 않음'이 answered로 처리됐다. 이 결과를 확인하고 생성 후 검증 및 구조화 유보 지침을 추가했다.

최종 비교에는 `before_live/`와 `final_live/`를 사용했다. 중간 실험을 삭제하거나 최종 결과로 섞지 않았다. 최종 Q01은 일수만 올바르게 답했으므로, 최종 단일 질문 응답만으로 분할 횟수 설명 능력이 검증됐다고 주장하지 않는다. 최종 Q27에서는 원문에 있는 분할 횟수와 사용구간 수를 함께 올바르게 설명했다.

## 6. 범위와 한계

- 실제 평가는 `RagService` 직접 호출이다. 브라우저·음성 입력·인증·HTTP handoff 변환까지 검증한 결과가 아니다.
- 실제 32문항은 질문마다 새 세션으로 실행했다. 다중 턴·요약·재전송·취소·세션 충돌은 기존 및 추가 로컬 테스트로 확인했다.
- 전후 같은 인덱스와 임베딩을 사용했다. 데이터 파이프라인의 검색 지표를 재계산하거나 임베딩 교체 효과를 평가하지 않았다.
- 정확 조회의 규정명 인식은 현재 다섯 규정과 숫자 조문 표기를 대상으로 한다. 별칭·조항 범위 표현 등 자연어 전체를 지원하는 파서는 아니다.
- 정확 조회는 해당 저장소의 docstore 인터페이스가 필요하고, 50개 청크 초과는 오류로 처리한다. 컨텍스트 예산 때문에 긴 조문의 모든 근거가 들어가지 못할 수도 있다.
- LLM의 단일 실행 결과이며 같은 입력에서도 다시 실행하면 달라질 수 있다. 새 holdout과 독립적인 사람의 검토가 필요하다.
- Q10과 Q28은 해결되지 않았다. 정상 질문 과도 유보를 줄이는 작업을 다음 우선순위로 권한다.

## 7. 원자료와 재현

비교 요약과 [문항별 비교 보고서](../../rag-code-template_ext/rag-service/evaluation/runs/improvement_20261026/case_comparison.md)는 저장소에 유지한다.

원자료는 다음 로컬 경로에 보존하며 Git에서는 제외한다:

```text
rag-code-template_ext/rag-service/evaluation/runs/improvement_20261026/
```

- `before_tests.txt`, `final_tests.txt`: 개선 전후 테스트 출력.
- `before_live/results.json`, `final_live/results.json`: 개선 전후 실제 API 원문 결과.
- `comparison.json`, `agent_review.json`, `comparison_context.json`: 집계, 에이전트 검토, 비교 설정.
- 각 실행의 `manifest.json`: 코드·인덱스·질문 해시와 실행 설정.

새 체크아웃에는 이 원자료가 없으므로 재집계에는 로컬 원자료 또는 새 평가 실행이 필요하다. 정확한 제외 목록과 재생성 정책은 [평가 생성물 Git 제외 정책](평가_생성물_Git_제외_정책.md)을 참고한다.

저장소 루트에서 로컬 회귀 테스트:

```bash
rag-code-template_ext/.venv/bin/python -m unittest discover -s rag-code-template_ext/rag-service/tests -v
```

보존된 자료만 다시 집계하며 외부 API를 호출하지 않는 명령:

```bash
rag-code-template_ext/.venv/bin/python rag-code-template_ext/rag-service/evaluation/compare_improvement.py rag-code-template_ext/rag-service/evaluation/runs/improvement_20261026
```

새 모의 실행은 `evaluate_improvement.py --output <새 폴더>`로 가능하다. `--live`를 추가하면 실제 자료를 외부 API로 전송하고 비용이 발생한다. 기존 결과 폴더를 덮어쓰지 않는다.
