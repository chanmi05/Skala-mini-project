# RAG 서비스 개선 요청 (데이터 파이프라인 → RAG 담당)

데이터 파이프라인 쪽에서 평가셋으로 검색 품질을 재 보고, **데이터 쪽에서 할 수 있는 개선은 끝냈어요.**
남은 문제는 `/rag-query`(검색 단계·프롬프트·응답)에서 고쳐야 해서 정리해 넘겨요.
각 항목에 **무엇이 문제인지 → 근거 수치/예시 → 어떻게 고치면 되는지** 순서로 적었어요.

| 바뀐 것 | RAG 쪽 영향 |
| --- | --- |
| (제안) 임베딩 모델 `ada-002` → `text-embedding-3-large` | 평가셋 MRR 0.778 → 0.823. 지금은 `.env.example`·`RUN.md`·평가 스크립트가 ada-002로 고정이라 **아직 바꾸지 않았어요.** 바꾸면 `OPENAI_EMBEDDING_MODEL`과 `faiss_db/pdf`를 함께 바꾸고 서버 재시작 필요 |

튜닝에 안 쓴 새 질문 12개(`data/eval/holdout_set.csv`)에서도 Hit@5 0.917, MRR 0.767로 비슷하게 나와요.

## 1. 조문 번호로 묻는 질문은 메타데이터 필터로 찾기

**문제**: "휴가규정 제12조 내용이 뭐야?" 같은 질문은 임베딩 검색으로는 못 찾아요. 5개 규정 모두 제12조가 있어서 **취업규정 제12조**가 1위로 나와요. 임베딩 모델을 바꿔도, 관련어를 붙여도 계속 실패했어요(평가셋 Q27).

**고치는 방법**: 질문에서 규정명과 조문 번호를 정규식으로 읽어, FAISS 검색에 `filter`를 걸어요. LangChain FAISS의 `similarity_search_with_score`가 `filter`를 지원해요.

```python
m = re.search(r"(취업|복리후생|근태|휴가|출장)\s*규정\s*제\s*(\d+)\s*조", prompt)
if m:
    flt = {"doc": f"스칼라테크 {m.group(1)}규정", "article": f"제{m.group(2)}조"}
    docs_scores = vectorstore.similarity_search_with_score(prompt, k=top_k, filter=flt)
else:
    docs_scores = vectorstore.similarity_search_with_score(prompt, k=top_k)
```

**검증한 것**: 위 코드로 Q27을 돌리면 휴가규정 제12조만 정확히 나와요.
규정명 없이 "12조 내용 알려줘"처럼 물으면 5개 규정이 다 후보라서, 그때는 `article`만 필터하고 답에서 어느 규정인지 되묻거나 다 보여 주는 게 좋아요.

## 2. 문서에 없는 질문은 "찾을 수 없음"으로 막기 (환각 방지)

**문제**: 예외 질문(문서에 답이 없는 질문)도 FAISS는 **항상 가장 가까운 청크를 돌려줘요.** 그래서 교재의 "검색 0건이면 LLM 호출 차단"이 작동하지 않아요. 거리로 거를 수도 없어요.

| 질문 (평가셋) | 1위로 검색된 조문 | 1위 거리 |
| --- | --- | --- |
| Q29 출퇴근할 때 회사 주차비 지원돼? | 출장규정 제6조 | 0.243 |
| Q30 사내 동호회 활동비 지원돼? | 복리후생규정 제8조 | 0.325 |
| Q31 올해 연봉 인상률이 몇 퍼센트야? | 휴가규정 제4조 | 0.392 |
| Q32 형제가 결혼하면 경조휴가 받아? | **휴가규정 제20조 경조휴가** | 0.303 |
| (비교) 정답을 1위로 찾은 질문들 | — | 0.20 ~ 0.40 |

예외 질문의 거리가 정답 질문과 같은 범위라서 "거리 0.35 넘으면 모른다" 같은 규칙은 쓸 수 없어요.

**특히 위험한 것**
- **Q32**: 경조휴가 조문이 검색되는데 표에는 "본인 혼인 5일"만 있어요. LLM이 형제 결혼도 5일이라고 지어낼 수 있어요.
- **Q29**: 출장규정의 "출장 중 주차비 실비"와 섞여 "주차비 지원된다"고 답할 수 있어요.

**지금 상태**: dev의 새 워크플로가 근거를 평가해서 `no_evidence`·`out_of_scope`면 `handoff: true`로 돌려줘요. 방향은 맞고, Q29~32에서 실제로 걸러지는지만 확인하면 돼요.

**더 막으려면**: 근거 평가 프롬프트에 규칙을 분명히 적어요.
- "질문의 대상(누가·무엇)이 규정 문장에 **그대로** 있을 때만 답한다. 비슷한 조문만 있으면 `N/A`"
- "규정에 없는 대상(형제자매 혼인, 출퇴근 주차 등)을 다른 항목으로 미루어 짐작하지 않는다"

**확인 방법**: 아래 4번의 답변 평가로 Q29~32가 모두 `handoff: true`로 나오는지 봐요.

## 3. top_k는 5 이상 유지하기

**문제**: dev의 새 `/rag-query`는 요청한 `top_k`를 그대로 써요(1~50). 그런데 음성 서버는 `top_k: 4`로 보내요.

**근거**: 지금 저장소에서 정답이 3위 안에 드는 비율 0.857, 5위 안 0.929예요. 정답이 4~5위에 있는 질문이 있어서(예: 출산휴가 4위, 수습 월급 4위) **k를 4 이하로 줄이면 그만큼 놓쳐요.**

**제안**: 음성 서버(`voice_pipeline.py`)가 보내는 `top_k: 4`를 **5**로 올리는 걸 추천해요.

## 4. 답변 품질 평가 (정확·근거·환각) 같이 돌리기

**문제**: 데이터 쪽 평가는 "검색이 정답 조문을 찾았나"까지만 재요. 교재 51쪽의 **정확·근거·환각** 판정은 `/rag-query` 답변이 있어야 해요.

**준비된 것**
- 평가셋: `data/eval/eval_set.csv` (32문항: 일반 28 + 예외 4, 기대답변·근거 조문·쪽 포함, 판정 칸 비어 있음)
- 새 질문 확인용: `data/eval/holdout_set.csv` (12문항)

**할 일**: 서버를 띄우고 평가셋 질문을 `/rag-query`에 보내 `answer`, `sources`를 판정 칸 옆에 기록 → 사람이 또는 LLM 평가자(교재의 LLM-as-a-Judge)로 정확·근거·환각을 채워요. 필요하면 데이터 쪽에서 질문을 일괄로 보내 답을 CSV로 모으는 스크립트를 만들어 드릴게요.

**특히 볼 문항**: Q06(5년 근속 연차, 계산 필요), Q28(복지포인트: "새로 두지 않는다"고 답해야 정답), Q29~32(예외).
