# 신규 인사규정 문서와 RAG 연결 방향

- 작성일: 2026-10-25 (Asia/Seoul)
- 목적: 특정 논문이나 파일명을 고정하지 않고 새로 등록한 인사규정 PDF의 내용에 따라 답변한다.
- 상태: 전처리 브랜치 코드 확인 및 연결 계획. 아래 보완 항목은 아직 구현·실제 데이터 실행 검증하지 않았다.

## 확인한 전처리 작업

원격 `data-preprocessing`을 fetch한 뒤 `origin/data-preprocessing`의 `8114245`를 읽었다. 현재 `dev-rag` 작업 디렉터리는 유지했으며 브랜치 전환·병합·인덱스 교체는 수행하지 않았다.

- `data/regulations/`: 취업·복리후생·근태·휴가·출장 규정 PDF 5종.
- `rag-code-template_ext/pdf_pipeline.py`: pypdf 페이지 추출 → 정제·구조 분석 → 고정 크기 또는 조문 청킹 → FAISS 적재.
- `rag-code-template_ext/ingest.py`: 폴더 일괄 적재와 `--dry-run` 지원. 기본 적재는 기존 PDF 인덱스를 삭제하며, `--keep`은 파일별 교체 방식이다. 실제 적재 명령은 실행하지 않았다.
- 해당 브랜치의 `/upload-paper`: 같은 파일명의 기존 청크를 교체하고 다른 파일은 유지하는 파이프라인을 호출한다.
- 메타데이터: source, doc, doc_no, version, doc_type, chapter, article, title, page, chunk_mode.
- 저장소 ID는 source와 청크 순번을 조합한다. 임베딩은 OpenAIEmbeddings의 기본값에 의존한다.

이 작업은 현재 브랜치의 세션 RagService에 아직 연결하지 않았다. 현재 로컬 평가의 영어 논문 인덱스는 인사규정 인덱스와 별개다.

## 재사용할 RAG 구조

현재 서비스는 검색 저장소와 LLM을 주입받으며 검색 결과의 텍스트·메타데이터를 사용한다. 한국어 답변을 지시하지만 영어 문서나 특정 논문을 강제하지 않는다. 근거 판단·제한된 재검색·출처 ID 검증·최근 대화·요약 흐름을 새 데이터에도 재사용한다.

```text
새 문서 등록
 → 형식·추출 가능 여부 검사
 → 원문 구조·적용 범위를 보존한 청킹과 메타데이터
 → 명시한 임베딩 모델로 적재
 → 새 인덱스·문서 범위를 서비스에 반영
 → 질문·최근 대화의 대상 해석
 → 선택 문서·적용 조건에 맞춘 검색
 → 근거 판단·필요 시 재검색
 → 문서명·페이지·조항이 연결된 답변 또는 확인 질문·유보
```

새 문서를 올릴 때마다 RAG 코드를 바꾸지 않는 것이 목표다. 파일 형식별 추출기와 검색 품질 검증은 필요하며 모든 PDF를 같은 정제 규칙으로 처리할 수 있다고 가정하지 않는다.

## 연결 전 보완할 부분

| 영역 | 확인한 현재 동작 | 보완 방향 |
|---|---|---|
| 구조 분석 | 첫 페이지 첫 줄을 제목으로 사용하고 SCT 문서번호·특정 버전 표기·한국어 장/조 패턴을 추정 | 표준 메타데이터와 선택적 도메인 파서를 구분하고 패턴이 없어도 원문 보존 |
| 정제 | 특정 법령 확인 근거/부록 제목부터 끝까지 제외하고 체크리스트 줄 제외 | 삭제 규칙을 분리하고 본문·별표·예외·신청 절차 누락 여부 검증 |
| 스캔·표 | pypdf 텍스트 추출 사용, OCR 경로 없음 | 추출 불가 명시 및 표의 행·열·대상·단위 보존 확인; 필요 시 별도 추출 경로 추가 |
| 문서 교체 | source 파일명으로 기존 청크 삭제 후 추가 | 문서 ID·버전·해시·교체 정책 확정; 동일 파일명 충돌과 다른 이름의 개정본 중복 처리 |
| 적재·동시 검색 | 기존 저장소를 삭제·추가로 직접 갱신하고 일괄 적재 기본값은 기존 디스크 인덱스 삭제 | 별도 경로에서 검증 후 교체; 요청별 검색 스냅샷·실패 복구 마련 |
| 임베딩 | 기본 모델 설정에 의존 | 색인·질의 임베딩 모델과 차원·인덱스 설정 명시 |
| 검색 범위 | 현재 RagService는 top_k만 검색기에 전달 | 문서·버전·시행일·적용 대상 필터 계약 추가. 시행일·적용 대상은 현재 전처리 메타데이터에 없음 |
| 조항 맥락 | 조문 또는 고정 크기 청크 검색 | 조건·예외·별표·인접 항·참조 조항 검색을 실제 질문으로 검증 |
| 출처 | 검색 메타데이터를 응답에 보존 | source/doc/page/article/title 안정적 매핑과 사실·인용 일치 검토 |
| 대화 기억 | 대화·요약은 보관하지만 문서 범위·개정 상태는 고정하지 않음 | 요청별 문서 범위·인덱스 버전 처리; 과거 답변을 현재 규정의 사실 근거로 사용하지 않음 |

시행일·직군 같은 조건은 자료나 사용자의 명시적 입력으로 확인할 수 있을 때만 적용한다. 메타데이터가 없는데 최신·적용 대상을 추측해 확정하지 않는다. 규정이 충돌하거나 적용 대상을 정해야 한다면 확인 질문 또는 근거 부족 응답을 사용한다.

## 다음 검증 순서

1. 전처리의 텍스트·메타데이터·문서 식별·임베딩 계약을 확정하고 현재 서비스와 연결한다.
2. 인사규정 5종의 추출·청킹 결과를 먼저 확인한다. 기존 영어 논문과 분리된 평가 데이터·인덱스·결과 폴더를 사용한다.
3. 근거가 있는/없는 질문, 복수 규정 비교, 적용 조건·예외·표·참조 조항, 최근 대화·과거 참조 질문을 구성한다.
4. 문서 추가·재업로드·다른 파일명의 개정본·삭제/교체 후 같은 질문을 재평가한다. 이전 내용 잔존과 출처 혼합을 검사한다.
5. 오프라인 검증 후 실제 LLM으로 검색 적중·답변/인용 정확도·확인 질문·유보·요약·토큰·지연을 측정한다.
6. 확인한 계약으로 기존 API·화면의 업로드·세션·질의를 연결한다.

기존 영어 논문의 top_k 결과나 질문별 실패 사례를 인사규정의 운영 기본값으로 일반화하지 않는다. 인사규정의 의미 품질은 실제 자료와 명시적인 검토 기준으로 평가한다.
