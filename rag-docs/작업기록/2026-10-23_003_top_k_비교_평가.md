# top_k 비교 평가

- 작업일: 2026-10-23 (Asia/Seoul)
- 브랜치: `dev-rag`
- 상태: 완료

## 요청과 목적

검색 개수를 여러 값으로 바꾸어 검색률·컨텍스트·응답 시간·토큰 사용량을 비교한다.

## 수행 내용 및 변경 파일

- 기존 k=5 기준 결과를 보존하고 k=3, 7, 10을 같은 질문 24개로 실제 평가.
- 실패 질문 7개의 기대 근거를 원문 청크와 다시 대조하고 질문 기준을 변경하지 않음.
- 모델·질문·RAG 모듈·컨텍스트 예산·출력 한도는 기준 실행과 동일하게 유지.
- `evaluation/runs/topk_{3,7,10}_20261023/`에 각 결과·설정·리포트 생성.
- `evaluation/compare_runs.py` 추가: 같은 설정·질문인지 검사하고 검색률·지연·토큰 집계.
- `evaluation/comparisons/topk_20261023/`에 전체 비교 결과와 질문별 검색 성공 기록.
- `tests/test_evaluation.py`에 설정 불일치·통계 계산 테스트 2개 추가.
- `evaluation/README.md`에 재실행·비교 집계 방법 추가.
- `soobin-docs/RAG_TOP_K_COMPARISON.md`에 비교 결과와 주요 답변 사례 기록.
- 기존 RAG 모듈, 서버, UI, 기본 top_k=5, 원본 저장소는 변경하지 않음.

## 검증 결과

질문 파일과 RAG 모듈의 해시가 기존 기준 실행과 동일함을 확인.
- 실제 외부 API 호출: 추가 72/72 성공. 기존 24개 포함 총 96개 결과 비교.
- Hit@k: k=3 60%, k=5 65%, k=7 80%, k=10 90% (답변 가능 질문 20개 기준).
- 평균 입력 토큰: 각각 약 1,019 / 1,633 / 2,222 / 3,085.
- 전체 응답 중앙값: 각각 약 1.63 / 1.78 / 1.69 / 1.77초.
- 오프라인 테스트 총 16개 통과. 설정이 다른 실행은 비교에서 거부하는 동작 확인.
- 각 실행에서 인덱스 불변 확인. 기존 기준 결과의 해시를 기록하고 보존.

## 남은 작업 및 제약

- 미해결 q03/q09의 검색 개선과 전 설정의 독립적인 답변 품질 검토가 필요.
- k=10이 검색 후보로 유망하지만 비용·인용 품질을 고려해 기본값 변경은 보류.
- 단일 실행의 지연은 변동성이 있으며, k=5는 이전 실행 결과를 재사용한다.
- 정답 기준은 에이전트 작성 기준이며 사람의 독립 검증은 아직 없다.
