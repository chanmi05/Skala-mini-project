# RAG 서비스 디렉터리 구조도 갱신

- 작업일: 2026-10-25 (Asia/Seoul)
- 브랜치: `dev-rag`
- 상태: 완료

## 요청과 목적

개발 중인 서비스의 디렉터리 구조를 환경 설정 파일까지 포함해 Markdown으로 저장한다. 기존 구조 문서가 있어 중복 생성하지 않고 현재 상태에 맞춰 갱신한다.

## 수행 내용 및 변경 파일

- `rag-code-template_ext/프로젝트 구조.md`: 기존 문서를 갱신했다. 독립 `rag-service`의 모듈·테스트·평가·문서와 상위 공용 `.env`·가상환경·의존성·FAISS 데이터의 위치를 트리로 정리했다. 모듈 연결도, 데이터 보관 위치, 환경변수 이름과 사용 범위, 기존 API와의 미연결 상태도 추가했다.
- `.env`와 프로젝트 `.venv`는 아직 없는 준비 위치로 표시했다. 환경변수 예시는 값이 비어 있으며 실제 비밀정보를 기록하지 않았다. 환경 파일이나 가상환경을 새로 생성하지 않았다.
- 기존 구조 문서의 PDF Q01~Q05 미구현 설명은 실제 소스에 구현이 존재해 현재 상태로 수정했다. 실제 외부 API 재검증을 했다는 뜻은 아니다.
- `rag-code-template_ext/rag-service/README.md`: 갱신한 구조 문서로 연결되는 링크를 추가했다.
- 이 작업 로그를 신규 생성했다. 기존 폴더 이동, 경로 수정, State·세션 구현, 평가 결과는 이전 작업이며 이번 변경에 포함하지 않는다.

## 검증 결과

- 실제 파일 목록·기존 서버 및 평가 스크립트를 읽어 구조와 책임 경계를 대조했다.
- 문서의 주요 파일·디렉터리와 상대 Markdown 링크 대상이 존재함을 확인했다. 준비 위치인 `.env`·`.venv`는 기존 파일과 구분했다.
- Markdown 코드 블록의 여닫힘과 `git diff --check`를 확인했다. Mermaid는 소스 구조만 확인했으며 별도 렌더링 검증은 수행하지 않았다.
- 문서 변경으로 Python 테스트·서버 기동·외부 LLM API 호출은 수행하지 않았다.

## 남은 작업 및 제약

- 문서에 표시한 환경 파일 생성·키 설정, 실제 세션 다중 턴 평가, 기존 API·화면 연결은 이번 요청의 범위에 포함하지 않는다.
