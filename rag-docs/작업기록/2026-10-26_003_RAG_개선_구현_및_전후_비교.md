# RAG 개선 구현 및 전후 비교

- 작업일: 2026-10-26 (Asia/Seoul)
- 브랜치: rag-preprocessing-integration
- 상태: 완료 (개선 구현·전후 검증·비교 문서 작성, 알려진 품질 실패 2건 기록)

## 요청과 목적

현행 코드의 테스트 결과를 먼저 기록하고, 앞서 논의한 개선 방향을 구현한 다음 같은 조건으로 다시 테스트하여 비교 자료를 문서로 저장한다. 코드 대상은 이전 요청에 따라 `rag-code-template_ext/rag-service/` 이하로 유지한다.

## 수행 내용 및 변경 파일

### 기존 변경 구분

시작 시 `data/eval/`, `rag-code-template_ext/eval_retrieval.py`, `rag-docs/rag-improve/`, 직전 리뷰 작업 로그는 기존 미추적 변경이었다. 원본 데이터·개선 전달 문서·기존 평가 코드는 이번 작업의 생성물로 취급하지 않았고 수정하지 않았다.

### 서비스 코드 변경

- `rag_agent.py`: 사실 답변의 유효 인용 검사, 적용 대상·조건·예외 지침.
- `rag_state.py`: 구조화 생성/검토 스키마와 검색 State 추가, 전체 모델 호출 한도 8→9.
- `rag_router.py`: 자립적인 문서 질문의 불필요한 회사명 확인 완화.
- `rag_workflow.py`: 선택 근거만 생성에 전달하고 출처를 재번호화, 생성의 유보 상태 반영, 생성 후 검증, 정확 조문 조회 경로.
- `rag_retrieval.py` 신규: 조문 파싱, docstore 메타데이터 매핑 캐시, 조문 모호성 확인 및 무관한 의미 검색 방지.
- 일반 의미 검색의 top_k=5는 유지했다. 음성 서버·프런트·데이터 파이프라인·환경 파일은 변경하지 않았다.

### 테스트·평가 및 문서

- `tests/test_rag_workflow.py`, `tests/test_memory_workflow.py`: 새 구조화 출력/검증 호출에 모의 모델과 호출 예산 경계 테스트를 맞췄다.
- `tests/test_rag_improvements.py` 신규: 고정 시나리오, 출처 제한, 재전송 인용 일치, 유보 저장, 검증 및 예산, 조문 조회 등을 검증한다.
- `evaluation/evaluate_improvement.py` 신규: 외부 호출 없는 고정 사례와 실제 32문항 평가, 질문별 결과/해시 저장.
- `evaluation/compare_improvement.py` 신규: 질문·인덱스·모델·k 동일 조건 및 리뷰 결과 해시 검사, 비교 집계.
- 서비스 `README.md`, `evaluation/README.md`: 동작·실행·한계 문서화.
- `evaluation/runs/improvement_20261026/`: 개선 전·중간·최종 원자료, 자동 테스트 출력, 에이전트 검토, 자동 집계 저장.
- `rag-docs/rag-improve/RAG_서비스_개선_전후_비교_2026-10-26.md`: 사용자용 전후 비교 문서.

### 실제 API 승인

최초 실제 API 평가 호출은 자동 승인 검토가 내부 규정/질문의 외부 전송에 구체적 승인이 없다는 이유로 거절했다. 외부 전송 없이 가능한 작업을 진행하면서 OpenAI 임베딩·LLM API에 32개 질문과 검색된 규정 청크를 전송하고 비용이 발생할 수 있음을 명시해 요청했다. 사용자가 '실제 API 평가 승인'으로 응답한 후 실제 평가를 실행했다. 비밀정보는 출력·기록하지 않았다.

### 중간 개선

- `after_fixture/`, `after_live/`에 생성 후 검증 이전 개선안의 결과를 보존했다.
- 실제 응답에서 숫자 설명 혼동과 명시되지 않음을 answered로 반환하는 상태 문제를 확인해 생성 후 검증과 유보 지침을 추가했다.

## 남은 작업 및 제약

- Q10 주 최대 근로시간은 최종 생성 후 검증에서 유보되어 기존 정상 핵심 답변을 잃는 회귀가 있다. Q28 복지포인트의 명시적 부정 규정도 여전히 답하지 못한다. 이 두 사례와 비용·지연 증가를 비교 문서에 명시했다.
- 32문항은 개발 중 참고한 자료여서 미사용 holdout으로 간주하지 않는다. 전달 문서에 언급된 `holdout_set.csv`는 현재 작업 트리에 없었다.
- 실제 평가는 RagService 직접 호출이며 브라우저·마이크·HTTP handoff까지 검증하지 않았다. 세션 재전송·요약·취소 등은 모의 로컬 회귀 검증이다.
- 생성 후 모델 검증도 오판할 수 있다. 의미적 근거의 완전한 보장이나 법률 검증을 주장하지 않는다.
- 원본 인덱스와 환경 설정은 변경하지 않았다. 임베딩 교체 및 음성 서버 k 조정은 범위 밖이다.
