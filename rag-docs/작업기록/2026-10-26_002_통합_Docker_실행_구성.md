# mini-project 통합 Docker 실행 구성

- 작업일: 2026-10-26 (Asia/Seoul)
- 브랜치: docker-deploy
- 상태: 완료

## 요청과 목적

8080·8008·8001·5173 서비스를 Docker Desktop의 mini-project 그룹 아래에서 한 번에 실행하고 RUN.md에 Docker 및 로컬 실행법을 구분한다.

## 수행 내용 및 변경 파일

- 루트 `docker-compose.yml`, `.env.example`: 네 애플리케이션과 MariaDB 통합, 공통 비밀값 참조, 서비스 DNS 연결, DB 및 모델 캐시 영속화.
- `workplace/Dockerfile`, `rag-code-template_ext/Dockerfile`, `frontend/Dockerfile`: 서비스 이미지 빌드 및 실행 진입점.
- 네 프로젝트의 `.dockerignore`: 비밀 환경 파일과 로컬 생성 파일을 빌드 컨텍스트에서 제외.
- `workplace/app/src/main/java/workplace/SimpleAuthServer.java`: DB_URL·DB_USER 환경 설정 지원, 기존 로컬 기본값 유지.
- `frontend/vite.config.js`: 컨테이너용 인증·음성 프록시 대상 환경 설정 지원.
- `RUN.md`: 통합 Docker와 로컬 실행 절차 분리, 환경 파일 위치와 포트·종료 명령 정리.
- 요청 이전부터 RUN.md에 HTML 5174 실행 안내를 제거한 미커밋 변경이 있었으며 이를 유지했다. 이 삭제를 이번 작업에서 새로 수행한 것으로 간주하지 않는다.
- 기존 음성 Dockerfile 및 개별 Compose 파일은 수정하지 않았다.

## 검증 결과

- `docker compose --env-file .env.example config --quiet`: 통과.
- `docker compose --env-file .env.example config --services`: 다섯 서비스 확인.
- `git diff --check`: 통과.
- `docker compose --env-file .env.example build`: 네 이미지 실제 빌드 성공. Java 컴파일 및 installDist, npm ci, RAG·음성 Python 의존성 설치 완료(음성 의존성은 기존 빌드 캐시 사용).
- 기존 서버에 영향을 주지 않도록 `mini-project-smoke` 임시 프로젝트, 호스트 포트 공개 제거, 인덱스 읽기 전용 마운트로 실제 Docker 기동 검증. 다섯 컨테이너 기동, MariaDB와 RAG healthy 확인.
- Vue HTML 200, Java 로그인 페이지 200, RAG `/health` 200, 음성 OpenAPI 200 확인.
- Vue 인증·음성 프록시 미인증 요청 401 확인. 최초 확인 스크립트는 인증 확인 경로를 200으로 잘못 기대하여 실패했으며 미인증 계약에 맞게 401로 수정한 후 통과했다.
- 임시 DB에서 Vue → Java → MariaDB 회원가입·로그인 성공, JWT 발급 후 Vue 인증 확인 200 및 음성 보호 HTML 200 확인. 토큰과 테스트 비밀번호는 로그에 기록하지 않았다.
- 검증에는 예제 비밀값과 Whisper tiny 모델을 사용했다. Hugging Face 모델 다운로드 및 실제 컨테이너 내부 HTTP/DB 연동 검증이며, OpenAI 음성·LLM·임베딩 API 호출 및 실제 질문 답변 검증은 하지 않았다.
- 검증용 컨테이너·네트워크·볼륨은 `down -v`로 제거했다. 빌드한 mini-project 이미지들은 유지한다.

## 남은 작업 및 제약

- 기본 Whisper small 모델의 다운로드·로딩 및 실제 키를 이용한 AI 응답, 브라우저 마이크·자동 재생은 이번 검증 범위에 포함하지 않았다. 실제 사용 전 루트 .env에 유효한 설정이 필요하다.
- 통합 DB는 기존 개별 Compose DB와 별도 볼륨이며 계정이 자동 이전되지 않는다.

## 후속 오류 수정: 루트 환경 파일 누락

- 사용자 실행 시 DB_PASSWORD·JWT_SECRET 보간 오류가 발생했다. 루트 `.env`가 없으며 개별 프로젝트 환경 파일에는 값이 있는 것을 확인했다.
- 로컬 전용 루트 `.env`를 생성하고 기존 workplace의 DB_PASSWORD·JWT_SECRET, 음성 프로젝트의 OpenAI 키 및 기존 모델 설정을 통합 구성에 맞게 복사했다. 기존 프로젝트 환경 파일은 수정하지 않았다. 비밀값은 출력·기록하지 않았다.
- `.env` 권한은 소유자 읽기·쓰기(600)이며 `git check-ignore .env`로 Git 제외를 확인했다.
- 로컬 음성 가상환경에 python-dotenv가 없어 최초 복사 스크립트는 변경 전에 실패했다. 기존 RAG Docker 이미지의 dotenv 파서를 사용해 파일 생성을 완료했다.
- `docker compose config --quiet`: 실제 루트 `.env`로 통과. 누락 오류를 해소했다. 이번 후속 작업에서는 전체 서버 기동이나 외부 AI API 호출은 수행하지 않았다.
- `RUN.md`에 같은 환경값 누락 오류의 원인·조치·검사 명령을 추가했다. 기존 빌드 및 임시 컨테이너 검증 결과는 위 기록과 같다.

## 최종 구성 변경: 폴더별 기존 .env 재사용

사용자가 기존 환경 파일이 있는데 루트에 다시 설정해야 하는 이유를 문의했다. 중복 설정이 필수인 것은 아니므로 루트 환경 파일을 요구하던 구성을 변경했다. **최종 구성은 이 절이 우선하며 위 루트 .env 생성·복사 안내는 이전 수행 내역이다.**

### 변경 파일과 내용

- `docker-compose.yml`: Java·MariaDB는 `workplace/.env`, 음성은 `voice-ai_code/.env`, RAG는 `rag-code-template_ext/.env`를 `env_file`로 읽는다. 루트 비밀값 보간을 제거했다. 컨테이너 내부 주소와 live 모드만 Compose에서 덮어쓴다.
- `workplace/docker/mariadb/entrypoint.sh`: 기존 DB_PASSWORD를 MariaDB 이미지의 MARIADB_PASSWORD에 매핑하고 공식 진입점을 실행한다. 비밀값을 출력하지 않는다.
- `RUN.md`: 폴더별 파일·필수 설정과 JWT 동일값 요구를 안내하고 루트 환경 파일 복사 안내를 제거했다.
- 앞선 작업에서 생성한 루트 `.env`와 `.env.example`은 생성 당시 값·내용과 일치하는 것을 확인한 후 제거했다. 각 프로젝트의 원래 환경 파일은 수정하지 않았다.

### 검증 결과

- `docker compose --env-file /dev/null config --quiet` 및 루트 환경 파일 제거 후 `docker compose config --quiet` 통과.
- 설정을 메모리에서 비교해 DB 비밀번호 공유, Java·음성 JWT 일치, 각 AI 키 로딩, Docker RAG 주소를 확인했다. 실제 값은 출력하지 않았다.
- `sh -n workplace/docker/mariadb/entrypoint.sh`, `git diff --check` 통과.
- 임시 `mini-project-smoke` 프로젝트에서 실제 폴더별 환경 파일로 다섯 서비스를 기동했다. 호스트 포트를 공개하지 않았으며 RAG 인덱스는 읽기 전용으로 마운트했다. MariaDB·RAG healthy 확인.
- 임시 DB 회원가입, Vue 프록시 로그인·JWT 발급, 인증 확인 200, 음성 보호 HTML 200 통과. Whisper는 검증용 tiny 모델을 사용했으며 실제 OpenAI API 호출은 하지 않았다.
- 검증용 컨테이너·네트워크·볼륨을 정리하고 실제 mini-project 서비스는 별도로 기동하지 않았다.

### 제약

- Java·음성 서버의 JWT_SECRET은 각 환경 파일에서 같은 값으로 관리해야 한다. 현재 파일은 일치함을 확인했다.
- 실제 AI 답변·음성 변환과 브라우저 마이크 검증은 이번 후속 범위에 포함하지 않았다.
