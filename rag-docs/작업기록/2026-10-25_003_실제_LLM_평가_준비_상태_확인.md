# 실제 LLM 평가 준비 상태 확인

- 작업일: 2026-10-25 (Asia/Seoul)
- 브랜치: `dev-rag`
- 상태: 로컬 준비 상태 확인 완료, 외부 API 검증 미수행

## 요청과 목적

실제 LLM 사용에 키가 필요한지, 현재 세션 RAG 평가를 위해 무엇이 준비되어 있고 무엇이 필요한지 확인한다. 키 값은 출력하지 않고 설정 여부만 확인한다.

## 수행 내용 및 변경 파일

- 실제 평가 스크립트, 의존성, 폴더 구조, Python 환경을 읽어 확인했다.
- 프로젝트·RAG·음성 서버의 알려진 `.env` 경로와 프로세스·사용자·시스템 OPENAI_API_KEY 설정 유무만 확인했다. 키 값·일부 문자열·길이는 출력하거나 기록하지 않았다.
- 이 작업 로그만 신규 생성했다. 코드·설정·기존 문서·인덱스는 변경하지 않았다. 키 발급·환경변수 등록·패키지 설치는 수행하지 않았다.
- OpenAI 공식 quickstart와 API 오류 안내를 확인했다. 기존 코드의 모델을 임의로 변경하지 않았다.

## 검증 결과

- `rag-code-template_ext/.env`, `rag-code-template_ext/rag-service/.env`, 루트 `.env`, `voice-ai_code/.env`, `voice-ai_code/app/.env`가 없었다.
- 현재 프로세스·Windows 사용자·시스템 환경변수에서 OPENAI_API_KEY가 설정되지 않았다.
- 프로젝트 `.venv`는 없다. 기본 등록 Python은 3.9지만 기존 저장소 밖 검증용 Python 3.12.14 가상환경을 사용할 수 있다.
- 검증용 환경에서 LangChain 1.2.7, langchain-core 1.7.0, langchain-openai 1.1.7, langchain-community 0.4.1, LangGraph 1.0.10, OpenAI 1.109.1, FAISS 1.15.1, python-dotenv 1.2.4가 설치된 것을 확인했다. 버전 조회 및 로컬 FAISS 읽기 외에 API 호출은 하지 않았다.
- PDF의 index.faiss와 index.pkl 존재·비어 있지 않음 확인. faiss.read_index로 벡터 44개·차원 1536을 읽었다. 기존 평가 질문은 24개다.
- 현재 실제 평가 코드는 GPT-4o와 text-embedding-ada-002를 사용한다. 동일 OpenAI 키를 두 클라이언트가 읽는 구조다. 실제 계정의 모델 접근 권한과 사용 한도는 확인하지 않았다.
- `run_workflow_smoke.py`는 session_store 없이 기존 history 호출을 평가하는 6개 사례 실행기다. 신규 세션·자동 요약의 실제 다중 턴 평가 실행기와 기대 결과 세트는 아직 추가되지 않았다.
- 평가만 수행할 때는 네이버 검색 키·MariaDB·Java 인증 서버·음성 서버·HTML 서버가 필요하지 않다. 기존 PDF 인덱스를 직접 사용한다.

## 남은 작업 및 제약

- 사용 가능한 OpenAI 키를 `rag-code-template_ext/.env`의 OPENAI_API_KEY 또는 실행 환경변수로 설정해야 한다. 채팅에 키를 전달할 필요는 없다.
- API 계정의 모델 권한·사용 가능 한도는 별도 확인해야 하며 실제 호출 전에는 키 유효성도 미확인이다.
- 신규 세션용 다중 턴 평가 실행기·질문 흐름·기대 결과를 만들고 기존 검증용 환경 또는 프로젝트용 Python 3.11 이상 가상환경에서 실행해야 한다.
- 실제 평가 시 질문 임베딩·분류·기억 해석·근거 판정·생성·요약에 외부 API가 사용된다. 이번 작업에서는 외부 API를 호출하거나 비용을 발생시키는 평가를 실행하지 않았다.
