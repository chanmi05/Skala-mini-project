## 수행 내용과 결과

### 1. 오프라인 단위 테스트 (외부 API 호출 없음)

### 2. 파이프라인 점검 (외부 API 호출 없음)

- 별도 점검 스크립트(대화 scratch 폴더, 저장소 외부)로 문서별 수치를 확인했다.

| 문서 | 문서번호 | 쪽 | 조문 | fixed 청크 | article 청크 |
|---|---|---|---|---|---|
| 취업규정 | SCT-HR-001 | 7 | 21 | 26 | 22 |

- 기존 `faiss_db/pdf` 인덱스: 벡터 115개, 1536차원, docstore 115개, 메타데이터 키 10종(article, chapter, chunk_mode, doc, doc_no, doc_type, page, source, title, version). 로드 전후 파일 해시가 같았다.
- 인덱스(115)와 현재 코드 fixed 결과(113)는 복리후생규정(16/15)·출장규정(23/22)에서 1개씩 다르다. 작업 011에서 기록한 차이와 같으며, 인덱스를 재생성하지 않았다.

### 3. 실제 OpenAI API 스모크 (외부 API 호출)

- `python -B rag-service/evaluation/run_hr_api_smoke.py --trust-local-index`
- GPT-4o와 text-embedding-ada-002를 사용했다. 임시 인덱스에서 실행했으며 원본 인덱스 해시는 유지됐다. 키 값은 출력·기록하지 않았다.

| 단계 | HTTP | 결과 |
|---|---|---|
| query_before | 200 | 출장규정 제12조 p.5 근거로 "복귀 후 10영업일 이내" 답변 |
| upload | 200 | 복리후생규정 재업로드 |
| stale_session | 409 | 문서 갱신 후 새 대화 안내 |
| query_after | 200 | 복리후생규정 제9조 p.3 근거로 본인 혼인 경조금 500,000원 답변 |
| followup | 200 | 같은 세션에서 "그 경조금"을 제9조로 해석 |
| end | 200 | 세션 종료 |
| closed_session | 404 | 종료한 대화 거부 |

## 제약·미완료

- 이 스모크는 고정 질문 2개와 후속 질문 1개뿐이다. 정확도 평가가 아니며, 세션 평가 9개 사례(`run_hr_session_evaluation.py`)는 이번에 다시 실행하지 않았다.
- TestClient로 앱을 직접 호출했다. uvicorn 서버 기동, 다중 워커, 인증, 음성·프론트 연동은 범위에서 제외했다.
- 답변의 출처 목록에는 질문과 관련성이 낮은 보조 근거(예: 다른 규정의 같은 조 번호)가 함께 포함된다. 답변 인용은 [S1]만 사용했다.
- 인덱스 115개와 현재 청킹 결과 113개의 차이는 해결하지 않았다. 재적재 여부는 별도 결정이 필요하다.

## 후속: 사용자 직접 실행 준비 (21:20)

- 사용자가 `uvicorn ... --port 8001` 실행 시 `WinError 10013` 발생. 원인은 오후 7:53부터 남아 있던 이전 세션의 RAG 서버(Codex 런타임 Python, `--reload` 없음)가 8001을 점유한 것이었다. 포트 제외 범위(50000~50059)와는 무관했다.
- 사용자 동의를 받아 해당 프로세스를 종료하고, 8001이 비어 있으며 재기동되지 않음을 확인했다. 서버 실행은 사용자가 직접 한다.
