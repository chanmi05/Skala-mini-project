# 음성 요청 쿠키 호스트 불일치 수정

- 작업일: 2026-10-26 (Asia/Seoul)
- 브랜치: docker-deploy
- 상태: 완료

## 요청과 목적

로그인 후 텍스트 질의가 실패한다는 요청. 첨부 응답은 403이 아닌 401이며, 127.0.0.1:5173 화면에서 localhost:8008로 요청하여 Cookie 헤더가 누락되었다. 로그인 → 질문·음성 재생 흐름에서 현재 출처의 인증 쿠키를 사용하도록 수정한다.

## 수행 내용 및 변경 파일

- `frontend/src/services/voice.js`: 개발·빌드 기본 음성 API 주소를 /voice-api로 통일. 기존 Vite 음성 프록시를 사용한다. 사용자 지정 VITE_VOICE_API_BASE_URL은 유지한다.
- `frontend/tests/voice-api.test.js`, `frontend/tests/voice-input.test.js`, `frontend/tests/speech-output.test.js`: 텍스트·녹음·오디오 요청의 프록시 경로 기대값 갱신. 기존 localhost 및 127.0.0.1 음성 URL도 프록시로 정규화되는지 확인한다.
- `frontend/README.md`, `RUN.md`: 직접 요청 안내를 프록시 방식으로 수정하고 호스트별 쿠키 구분을 설명한다.
- 기존 Docker 구성, Java DB 설정, Vite 프록시 환경 설정 및 RUN.md의 기존 미커밋 변경은 이전 요청의 작업이며 이번 변경으로 새로 작성한 것으로 간주하지 않는다.
- 실행 중인 mini-project의 frontend 이미지 빌드 및 프런트 컨테이너만 재생성했다. 실제 DB·백엔드는 재시작하지 않았다.

## 검증 결과

- Docker 프런트 이미지 빌드 성공.
- `docker run --rm mini-project-frontend npm test`: 모의 요청·응답을 사용하는 기존 프런트 회귀 테스트 38개 통과.
- `docker run --rm mini-project-frontend npm run build`: 성공.
- 실제 브라우저 검증: voice-auth-smoke 임시 프로젝트에서 호스트 127.0.0.1:15173로 가입·로그인했다. 실제 mini-project DB에는 테스트 계정을 추가하지 않았다.
- 로그인 전 POST /voice-api/voice-query-text는 401, 로그인 후 /api/auth/check와 /voice-api/voice-config는 각각 200. 로그인 후 같은 POST 경로에 빈 질문을 전송해 422 입력 검증 응답을 확인했다. 인증 경계를 통과한 검증이며 유효한 질문으로 실제 RAG 답변을 생성한 검증은 아니다.
- 브라우저가 로드한 모듈의 VOICE_API_BASE_URL=/voice-api 확인. 로그인 UI에 테스트 계정 이름이 표시되는 것을 확인했다. Cookie·JWT·비밀번호 값은 로그에 기록하지 않았다.
- 브라우저 도구 기본 샌드박스 실행이 실패하여 권한 확장으로 실행했다. 도구 업데이트 알림은 안내했으며 업그레이드하지 않았다. 검증 TaskSpace는 종료했다.
- 임시 컨테이너·네트워크·볼륨 정리. 실행 중인 실제 mini-project는 수정한 frontend만 재생성한 상태로 유지.
- git diff --check 통과.

## 남은 작업 및 제약

- 외부 AI API와 마이크·음성 인식 자체는 이번 인증 수정 범위에 포함하지 않는다.
- 쿠키는 localhost와 127.0.0.1 사이에 공유되지 않으므로 호스트를 바꿔 접속할 때 다시 로그인해야 한다.
