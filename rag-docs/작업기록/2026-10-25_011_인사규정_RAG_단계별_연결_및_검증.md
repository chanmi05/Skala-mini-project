# 인사규정 RAG 단계별 연결 및 검증

- 작업일: 2026-10-25 (Asia/Seoul)
- 브랜치: `rag-preprocessing-integration`
- 상태: RAG 데이터·API·업로드·실제 LLM·콘솔 연결 및 검증 완료, Java 인증 환경 오류와 실제 로그인 전체 기동 검증은 남음

## 요청과 목적

전처리 머지 이후 데이터 점검, 새 RagService/API 연결, 업로드 반영, 실제 LLM 다중 턴 평가, 화면 통합을 순서대로 수행한다. 이 요청의 연속 작업을 하나의 로그로 관리했다. 작업 시작 시 Git은 깨끗했으며 머지 결과와 기존 규정 인덱스는 이전 작업이다.

## 단계별 수행 내용 및 변경 파일

### 1. 데이터 점검

- 인사규정 PDF 5종을 fixed/article 두 모드로 dry-run했다. PDF 스킬에 따라 휴가규정 2쪽을 렌더링해 추출 순서를 표본 대조했다. 모든 페이지의 표/병합 셀을 시각 검증한 것은 아니다.
- `rag-code-template_ext/rag-service/evaluation/inspections/hr_20261025/`: 점검 JSON·Markdown·최종 콘솔 화면을 저장했다.
- 기존 인덱스는 115개·1536차원, 현재 fixed 재청킹은 113개, article은 96개다. 기존 파일을 자동 재생성하거나 덮어쓰지 않았다. 문서가 초안·회사 미확정 항목을 포함한다는 상태를 답변 경계에 반영했다.

### 2. API·세션·출처 연결

- `rag-code-template_ext/rag-service/rag_api.py` 신규: FastAPI 앱 팩토리, 세션 생성/종료, query·upload-paper, 설정 지연 초기화, 소유권 구분, 입력 검증, 안전한 공개 응답을 구현했다. 원본 청크·프롬프트·내부 trace는 공개하지 않는다.
- `rag-code-template_ext/rag_external-web_pdf_closed_llm.py`: 기존 uvicorn 모듈명을 유지한 얇은 진입점으로 바꿨다. 기존 prompt/response와 현재 answer/output·sources·needs_review·handoff·warning을 함께 반환한다. 실제 서비스 경로에서 기존 중복 동기 RAG 함수를 실행하지 않는다.
- `rag-code-template_ext/rag-service/rag_router.py`: top_k별 서비스가 같은 SessionCoordinator를 사용할 수 있게 했다. SDK가 직접 던지는 Pydantic 오류도 판정 형식 오류로 분류한다.
- `rag-code-template_ext/rag-service/tests/test_rag_api.py` 신규: 기존 응답 호환, 초기/기존 세션 재전송, 소유권, 종료, top_k 적용, 업로드 교체·실패·롤백, 요약 실패 표시를 검증한다.

### 3. 인덱스 갱신과 업로드

- `rag-code-template_ext/pdf_pipeline.py`: 임베딩 모델을 명시하고 테스트 의존성 주입, 인덱스 복제, 별도 디렉터리 완성 후 교체·실패 롤백을 추가했다. 무관한 파일이 있는 디렉터리를 교체하지 않도록 검사한다. 소스 PDF 정제·조문 인식 규칙은 변경하지 않았다.
- `rag-code-template_ext/ingest.py`: .env를 옵션 처리 전에 로드하고 --output-dir를 추가했다. 기존 인덱스를 먼저 삭제하지 않고 새 인덱스 완성 후 교체한다. 실제 일괄 재적재는 실행하지 않았다.
- 업로드를 직렬화하고 준비된 인덱스·revision·서비스 캐시를 잠금 안에서 교체한다. 질의는 같은 snapshot의 서비스·인덱스·revision을 사용한다. 기존 source 파일만 교체하며, 이전 revision의 대화는 409로 새 대화를 안내한다.

### 4. 실제 LLM 평가와 보완

- OpenAI Docs의 GPT-4o·Structured Outputs 문서와 기존 코드 설정을 확인했다. 기존 모델 GPT-4o와 임베딩 text-embedding-ada-002를 유지했다. 제공된 .env를 사용해 api.openai.com의 실제 인증·모델 접근을 확인했으며 비밀값을 출력하거나 기록하지 않았다.
- `rag-code-template_ext/rag-service/evaluation/run_hr_session_evaluation.py` 신규: 규정에서 미리 작성한 기대값으로 9개 다중 턴 사례를 실행하고 새 결과 폴더·모듈/인덱스 해시·사용량·요약 스냅샷을 기록한다. 오류 시 같은 평가를 무조건 계속 호출하지 않는다.
- `rag-code-template_ext/rag-service/evaluation/run_hr_api_smoke.py` 신규: 원본과 분리된 임시 인덱스에서 실제 임베딩 업로드와 query·followup·종료를 검증한다. 임시 인덱스는 종료 시 정리한다.
- 실제 모델의 MemoryDecision 필드 조합 오류, 새 문서 질문의 불필요한 요약 조회, 과거 참조 실패를 발견했다. `rag_state.py`, `rag_workflow.py`, `rag_session.py`에 분기별 중첩 union, strict schema, summary_available 전달과 판정 지침 보완을 적용했다. 내부 MemoryDecision 검증은 유지했다. 테스트 더블은 새 wire schema와 strict 옵션을 지원하도록 변경했다.
- 브라우저 반복에서 사용하지 않는 reason_code의 빈 문자열 때문에 정상 분류가 거부되는 경우를 확인했다. 새 InputDecision·기억 wire schema에서 불필요한 설명 필드를 제거하고 제어 사유는 코드가 만든다. 레거시 RouteDecision/EvidenceDecision 설명의 빈 값은 허용하되 업무 필드·상호 배타 검증은 유지했다. 회귀 테스트를 추가하고 실제 세션·API 평가를 재실행했다. 공개 오류는 안전하게 유지하고 서버에는 사유·오류 종류만 로깅한다.
- 세션 평가 7회와 API 평가 3회를 보존했다. 초기 실패·부분 성공 결과를 삭제하지 않았다. 별도 진단용 구조화 호출과 브라우저 질의도 수행했으며 평가 manifest 수치에 모두 포함되는 것은 아니다.
- 최종 세션 실행: `hr_session_20261025T105257260569Z`, 기대 상태 9/9, 지정 표현·지정 출처 조건·과거 참조 요약 확인 충족. 모델 34회, 입력 실사용 41,889토큰, 9개 지연 중앙값 약 3.72초. 인사·요약 갱신을 포함하고 STT/TTS는 제외한다.
- 최종 API 실행: `hr_api_20261025T105257588628Z`. 질의 200 → 실제 PDF 업로드 200 → 이전 대화 409 → 새 질의 200 → 후속 질문 200 → 종료 200 → 종료 대화 404. 원본 인덱스 해시 동일.
- 이 결과는 독립 평가나 일반적인 정확도 100%를 뜻하지 않는다. 제공된 규정 초안에 대한 개발용 고정 샘플이며 실제 법률·회사 정책의 적합성 검증은 아니다.

## 최종 검증 결과

- RAG·세션·HTTP·업로드 오프라인 테스트 94개 통과.
- 음성 게이트웨이 테스트 41개 통과. 최초 3건은 FFmpeg 부재로 실패했으며, 저장소 밖 검증 환경에 imageio-ffmpeg를 준비하고 테스트 프로세스 PATH에만 실행 파일을 추가해 통과했다. 실제 Whisper·TTS 호출은 모의했다.
- Vue 프론트 테스트 38개 통과, Node 24.22.1의 Vite 프로덕션 빌드 성공. 위 오프라인 테스트 합계 173개다.
- 실제 LLM·임베딩 평가와 브라우저 콘솔 확인은 위 모의 테스트와 별도 수행했다.
- Java 인증 Gradle :app:test는 --no-daemon 재시도에서도 Unable to establish loopback connection으로 테스트 실행 전에 실패했다. 통과로 기록하지 않는다.
- JVM 시작 시 IPv4 우선 옵션을 테스트 프로세스에만 적용해 한 번 더 확인했으나 같은 Gradle 루프백 오류였다. 전역 Java 설정이나 저장소의 Gradle 설정은 바꾸지 않았다.
- 구문·문서 링크·HTML 스크립트 문법·공백 오류와 원본 인덱스 보존을 최종 점검했다. 생성된 빌드·검증 의존성은 Git 제외 대상이다.

## 남은 작업 및 제약

- workplace/.env의 JWT_SECRET과 실제 DB/로그인 실행 환경이 없어 로그인 → Vue → 음성 → RAG 전체 서버 기동은 수행하지 않았다. Java 환경 오류 해결과 함께 별도 확인이 필요하다.
- RAG 단독 API는 기존 로컬 공개 API다. 소유권 구분은 사용자 JWT 검증을 대체하지 않는다. 배포용 인증·업로드 권한·다중 워커 공유 저장소는 별도 범위다.
- session_facts 자동 저장, OCR, 모든 표의 의미 보존, 시행일/적용 대상 필터, 다른 파일명의 개정본 판별은 구현하지 않았다.
- 원본 PDF·원본 115개 인덱스·기존 논문 평가 결과·기존 작업 로그·실제 키를 보존했다. 이번 작업은 아직 커밋/푸시하지 않았다.
