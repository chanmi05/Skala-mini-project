# LangChain 라우터·LangGraph 문서 흐름 구현

- 작업일: 2026-10-23 (Asia/Seoul)
- 브랜치: `dev-rag`
- 상태: 구현·모의 테스트·소규모 실제 연동 확인 완료, 기존 서버 연결 전

## 요청과 목적

입력 분기는 LangChain, 문서 질문은 개별 Python 모듈의 LangGraph로 처리하고
State 정의를 논의할 수 있는 구조를 구현한다. 기존 서버는 보존한다.

## 수행 내용 및 변경 파일

- `rag_state.py`: 공통 스키마·설정과 요청별 TypedDict State.
- `rag_router.py`: LangChain LCEL/RunnableBranch 및 공개 비동기 진입점.
- `rag_workflow.py`: 상태 그래프·근거 판단·기본 1회/최대 2회 재검색과 종료 조건.
- `rag_agent.py`: 기존 생성·출처 검증 부분을 `generate_answer()`로 분리해 재사용.
  기존 `answer_question()` 인터페이스는 유지.
- `requirements-rag-workflow.txt`: 기존 requirements를 포함하고 LangGraph 직접 의존성 명시.
- `tests/test_rag_workflow.py`: 실제 Runnable/Graph를 사용하는 모의 모델 경로 검증 추가.
- `evaluation/run_workflow_smoke.py`: 공개 논문 대상 소규모 실제 연동 실행기 추가.
- `soobin-docs/RAG_ROUTER_WORKFLOW_USAGE.md`: 호출법·State 초안·제약·추가 논의 항목 정리.
- 기존 전략 문서에 최신 구현 안내 링크 추가.
- 기존 API·UI·저장소·패키지 설치 상태는 변경하지 않음.

## 검증 결과

- 기존 16개와 신규 22개, 오프라인 테스트 총 38개 통과.
- 검증: 입력·인사·모호함·후속 질문, 0/1/2회 재검색, 중복 질의·무진전 종료,
  잘못된 출처·분류, 호출/입력 예산, 장애·시간 초과·취소, 동시 요청 상태 분리.
- 첫 실제 연동 후 구조화 출력 토큰 보정·원질문 보존을 보완하고 최종 코드로 6개 입력 재확인.
- 최종 결과: `evaluation/runs/workflow_smoke_20261023_v2/`에 저장. 코드 해시 일치 확인.
- 인사·모호한 입력·문서 질문·후속 질문·정보 부재·마스킹 질문의 기대 상태 6/6 일치.
- 정보 부재 질문은 총 검색 2회·재검색 1회 후 유보. 문서 질의는 모델 3~4회 호출.
- 문서 질의 전체 약 3.94~5.64초. 음성 전체 1~2초 목표를 충족했다고 판단하지 않음.
- 생성된 인코더/디코더 층 수·마스킹 답변은 출처와 에이전트 1차 대조.
- 인덱스 변경 없음. 기존 FastAPI·화면은 여전히 이전 경로이며 새 코드로 연결하지 않음.

## 남은 작업 및 제약

- 실제 모델의 분류·근거 판정 품질은 별도 평가가 필요.
- State의 대화 저장·문서 도메인 메타데이터·세션 범위는 사용자와 추가 논의.
- 모델·저장소는 State에 넣지 않고 의존성 주입으로 유지.
- 출력 토큰 한도는 주입 모델에서 설정. 입력 예산은 사전 추정 및 실제 usage 사후 보정이므로
  완전한 외부 비용 상한은 아님. 분류 스키마 토큰 등의 차이를 문서에 명시.
- 커밋·푸시는 수행하지 않음.
