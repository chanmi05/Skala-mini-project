# 인사규정 전처리 브랜치 및 연결 방향 확인

- 작업일: 2026-10-25 (Asia/Seoul)
- 브랜치: `dev-rag`
- 상태: 코드 확인·연결 계획 문서화 완료, 연동 구현 전

## 요청과 목적

사용자가 인사규정 PDF 등의 신규 등록을 도메인으로 설명하고 data-preprocessing 브랜치의 기존 작업을 알려 주었다. 새로 등록한 문서에 따라 재사용할 RAG의 현재 구조와 보완 지점을 확인한다.

## 수행 내용 및 변경 파일

- `git fetch origin data-preprocessing` 후 `origin/data-preprocessing`의 `8114245` 트리·pdf_pipeline.py·ingest.py·기존 업로드 API를 읽었다. 규정 PDF 5종과 정제·고정/조문 청킹·메타데이터·source 기준 교체 적재를 확인했다.
- 현재 RagService의 검색·State·세션 계약과 대조했다. 특정 문서 형식에 의존하는 파서·삭제 규칙, 파일명 기준 교체, 검색 범위/버전 필터, 인덱스 갱신 일관성, 표·OCR 등의 확인 지점을 정리했다.
- `rag-docs/HR_DOCUMENT_INTEGRATION_PLAN.md` 신규: 브랜치 확인 결과와 연결 계약·보완 항목·새 규정 추가/교체 평가 순서를 기록했다.
- `rag-docs/RAG_DEVELOPMENT_PLAN.md`: 확인한 도메인과 새 연결 방향 문서 링크를 추가했다.
- 이 작업 로그를 생성했다. 브랜치 전환·병합·전처리 코드 복사·PDF 적재·인덱스 교체는 수행하지 않았다. 기존 미커밋 변경과 사용자 환경 파일은 보존했다.

## 검증 결과

- 원격 브랜치 fetch와 Git 객체 읽기 성공. 전처리 구현 확인은 정적 코드 검토이며 규정 PDF의 실제 추출·청킹·RAG 답변 품질을 검증한 것은 아니다.
- 새 문서와 연결 문서의 상대 Markdown 링크·코드 블록 확인, `git diff --check` 통과.
- 실행 테스트·외부 임베딩/LLM API 호출은 수행하지 않았다. 기존 영어 논문 인덱스·평가 결과를 변경하지 않았다.

## 남은 작업 및 제약

- 문서/메타데이터·임베딩·업로드 교체 계약 확정 후 전처리와 세션 서비스를 연결해야 한다.
- 인사규정용 별도 인덱스·평가 질문과 신규 문서/개정본 교체·다중 턴 평가가 필요하다.
- 모든 PDF를 현재 정제 규칙으로 처리할 수 있다고 가정하지 않는다. 실제 자료의 표·예외·부록 보존 및 스캔 문서 처리도 검증해야 한다.
