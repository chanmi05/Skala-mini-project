# 전처리 코드 및 규정 PDF 반영

- 작업일: 2026-10-25 (Asia/Seoul)
- 브랜치: `rag-preprocessing-integration`
- 상태: 요청한 파일 반영 완료, 전처리 실행·RAG 연결 전

## 요청과 목적

사용자가 계획의 1번 작업인 전처리 코드 2개와 규정 PDF 폴더 가져오기를 직접 수행하도록 요청했다.

## 수행 내용 및 변경 파일

- 작업 시작 시 현재 브랜치와 미커밋 변경이 없음을 확인했다. 대상 파일·폴더가 없어 기존 사용자 파일과 겹치지 않았다.
- `git fetch origin data-preprocessing` 후 소스 `origin/data-preprocessing`의 `8114245`에서 다음 파일을 작업 디렉터리로 가져왔다.
  - `rag-code-template_ext/pdf_pipeline.py`
  - `rag-code-template_ext/ingest.py`
  - `data/regulations/01_취업규정.pdf`
  - `data/regulations/02_복리후생규정.pdf`
  - `data/regulations/03_근태규정.pdf`
  - `data/regulations/04_휴가규정.pdf`
  - `data/regulations/05_출장규정.pdf`
- `git restore --source=origin/data-preprocessing --worktree -- ...`로 위 경로만 반영했다. 브랜치 전체 병합, 기존 API·인덱스·환경 파일 수정은 수행하지 않았다.
- 이 작업 로그를 신규 생성했다. 스테이징·커밋은 수행하지 않았다.

## 검증 결과

- 가져온 7개 파일의 Git blob 해시가 소스 브랜치와 모두 일치함을 확인했다.
- Python 파일 2개를 실행하지 않고 compile()로 구문 검사해 통과했다.
- Git 상태에서 대상 파일 외에 기존 추적 파일의 변경이 없음을 확인했다. `git diff --check` 통과.
- 실제 PDF 추출·청킹, 의존성 import 테스트, 인덱스 생성, 외부 임베딩·LLM API 호출은 수행하지 않았다.

## 남은 작업 및 제약

- 다음 단계는 의존성 준비 후 `ingest.py --dry-run`으로 추출·청킹 확인이다.
- 기본 적재 명령은 기존 PDF 인덱스를 삭제하므로 실제 적재 전 규정용 출력 경로 분리가 필요하다.
- 이번 반영만으로 새 RagService나 기존 업로드·질의 API에 연결된 것은 아니다.
