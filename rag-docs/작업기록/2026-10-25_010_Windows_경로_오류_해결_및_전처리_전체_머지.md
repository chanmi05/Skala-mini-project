# Windows 경로 오류 해결 및 전처리 전체 머지

- 작업일: 2026-10-25 (Asia/Seoul)
- 브랜치: `rag-preprocessing-integration`
- 상태: 머지 오류 해결 및 전체 반영 완료, 외부 API·전체 서비스 연동 검증 전

## 요청과 목적

사용자가 전체 머지 시 Windows의 invalid path와 미추적 파일 덮어쓰기 오류를 보고했다. 원본 브랜치와 현재 작업을 보존하면서 머지가 가능하도록 해결한다.

## 원인과 이전 확인의 한계

- 원격 브랜치의 `APIS-11:30.md`는 Windows 파일명에 사용할 수 없는 콜론을 포함한다.
- 앞서 가져온 전처리 코드·규정 PDF 7개가 미추적 상태여서 merge의 덮어쓰기 보호에 걸렸다.
- 이전 `merge-tree` 확인은 Git 객체 간 병합 가능성을 확인했을 뿐 Windows 작업 디렉터리의 파일명 제약과 미추적 파일 문제를 검증하지 못했다. 해당 제한을 놓친 기존 안내를 정정한다.

## 수행 내용 및 변경 파일

- 미완료 MERGE_HEAD가 없는 것과 현재 미추적 파일을 확인했다. 전처리 원격 트리 전체의 Windows 금지 문자·예약 이름·끝 공백/마침표를 검사해 문제 경로가 위 파일 1개임을 확인했다.
- 기존 전처리 파일 7개와 이전 작업 로그 008·009만 명시적으로 스테이징해 `d384718`로 커밋했다. 사용자의 미추적 작업을 삭제하지 않았다.
- `origin/data-preprocessing`의 `8114245`를 부모로 하는 로컬 `codex/data-preprocessing-windows-compat` 브랜치를 생성했다. `APIS-11:30.md`를 `APIS-11_30.md`로 바꾼 커밋은 `e4eb383`이다. 파일 내용과 다른 경로는 동일하다.
- 잘못된 파일명을 Windows에 체크아웃하지 않고 Git root tree와 commit 객체를 만들어 호환 커밋을 생성했다. core.protectNTFS 설정은 변경하지 않았다. 원본 data-preprocessing 브랜치·원격은 변경하거나 푸시하지 않았다.
- 현재 브랜치에서 호환 브랜치를 `--no-ff --no-commit`으로 머지해 실제 파일 반영이 성공했다. 전처리·인사규정 인덱스 외에 해당 브랜치의 프론트·음성·인증 변경도 함께 들어왔다.
- 현재 rag-service·기존 rag-docs·AGENTS.md와 `.env`는 보존했다. 이 로그를 머지 결과에 추가하고 머지 커밋으로 마무리했다.
- 프론트 검증을 위해 `npm ci --ignore-scripts --no-audit --no-fund`로 lockfile 기준 의존성을 설치했다. node_modules는 Git 제외 대상이며 package.json·lockfile을 임의 수정하지 않았다.

## 검증 결과

- 실제 파일 머지 성공, Git 충돌 경로 없음. Windows 호환 커밋은 원본 대비 파일명 1건의 100% rename이다.
- RAG: Python 3.12 검증 환경에서 `python -B -m unittest discover -s rag-code-template_ext/rag-service/tests`, 83개 통과.
- 프론트: 최초 node --test는 Vue 미설치로 import 오류가 있었다. 의존성 설치 후 기존 Node 22.16의 엔진 경고를 피하도록 제공된 Node 24.22.1로 --test를 실행해 35개 모두 통과했다. 프론트 프로덕션 빌드·브라우저 실행은 수행하지 않았다.
- 인증: Gradle :app:test가 java.io.IOException: Unable to establish loopback connection으로 테스트 실행 전 실패했다. --no-daemon 및 IPv4 우선 옵션으로 1회 재확인해 같은 환경 오류를 확인했다. 인증 테스트 통과로 기록하지 않는다.
- `.env` 존재·Git 제외 및 미추적 상태를 확인했다. 비밀값은 읽어 출력하거나 로그에 기록하지 않았다.
- `git diff --cached --check`로 공백 오류를 확인했다. 외부 LLM·임베딩 호출, PDF 재적재, 음성 모델 실행은 수행하지 않았다.

## 남은 작업 및 제약

- Gradle 루프백 환경 문제 해결 후 인증 테스트 재실행이 필요하다. 음성 서버 전체 테스트와 전체 서비스 기동은 검증하지 않았다.
- 머지로 PDF 인덱스가 인사규정용으로 반영되지만 새 RagService의 API 연결은 별도 작업이다. 기존 영어 논문 평가를 새 인덱스로 그대로 재사용하지 않는다.
- 로컬 커밋·머지만 수행했으며 원격 푸시는 수행하지 않았다.
