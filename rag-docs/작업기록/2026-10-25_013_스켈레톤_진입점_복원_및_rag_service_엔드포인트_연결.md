# 스켈레톤 진입점 복원 및 rag-service 엔드포인트 연결

- 작업일: 2026-10-25 (Asia/Seoul)
- 브랜치: `rag-preprocessing-integration`
- 결과: `original/rag_external-web_pdf_closed_llm.py`의 스켈레톤 구조를 `rag-code-template_ext/rag_external-web_pdf_closed_llm.py`에 복원하고, 내부 엔드포인트(`/upload-paper`, `/rag-query`, `/sessions`, `/console`, `/health`)를 `rag-service`와 연결 완료. 오프라인 테스트 94개 및 진입점 모의 질의 통과.

## 요청·목적

`original/rag_external-web_pdf_closed_llm.py`에 있는 기존 스켈레톤 코드 기반 파일을 다시 진입점으로 삼고, 내부 엔드포인트 구현을 `rag-service`(`RagRuntime` / `RagService`)와 연결하도록 리팩터링한다.

## 실제 변경 파일

- 수정: `rag-code-template_ext/rag_external-web_pdf_closed_llm.py`
- 신규: `rag-docs/작업기록/2026-10-25_013_스켈레톤_진입점_복원_및_rag_service_엔드포인트_연결.md`
- 이번 작업 전부터 워킹 트리에 남아 있던 다른 미커밋 변경분은 이번 작업에서 만든 것이 아니다.

## 수행 내용

1. **스켈레톤 골격 복원**:
   - `original/rag_external-web_pdf_closed_llm.py`의 헤더 주석, import 구성, `.env` 로드, `ASYNC_DB_URL`/`engine`, 전역 `app = FastAPI(...)` 및 `CORSMiddleware`, 전역 `VECTORSTORE_WEB`/`VECTORSTORE_PDF` 초기화 및 로드 출력, `load_paper`, `RAGRequest`, `AnswerResponse`, `extract_by_marker`, `fallback_extract_from_context`, `[Q03]`·`[Q04]`·`[Q05]` 주석 구조를 `rag-code-template_ext/rag_external-web_pdf_closed_llm.py`에 복원했다.
2. **내부 엔드포인트를 `rag-service`에 연결**:
   - 모듈 시작 시 로드한 `VECTORSTORE_PDF`·`VECTORSTORE_WEB`을 `RagRuntime`(`app.state.rag`)에 연결했다.
   - `@app.post("/upload-paper")`: PDF 확장자·크기 검증 후 `rt.upload(data, source)`(`pdf_pipeline.parse_pdf` → `chunk` → `clone_store` → `upsert` → `save_store`)를 실행하고 전역 `VECTORSTORE_PDF`와 스냅샷 버전을 함께 갱신하도록 연결했다.
   - `@app.post("/rag-query")`: `source`(`"pdf"` / `"web"`) 판별 및 세션 생성·검증 후 `rt.snapshot_service(source, rag_request.top_k)`에서 `RagService`(LangChain 입력 라우터 + LangGraph 워크플로우)를 가져와 `await service.ainvoke(...)`를 호출하고, 기존 `prompt`/`response`와 확장 필드(`answer`, `output`, `sources`, `status`, `needs_review`, `handoff`, `warning`, `session_id`, `request_id` 등)를 함께 반환하도록 연결했다.
   - 콘솔·프론트·음성 서버 연동에 필요한 `/health`, `/console`, `POST /sessions`, `DELETE /sessions/{sid}` 엔드포인트도 진입점 `app`에 함께 정의했다.

## 후속: 실제 uvicorn 서버 기동 및 HTTP API 호출 검증 (22:05)

- `uvicorn rag_external-web_pdf_closed_llm:app --host 127.0.0.1 --port 8001`을 실제로 기동한 뒤 `httpx.Client`로 HTTP 엔드포인트를 호출해 검증했다(실제 OpenAI GPT-4o / text-embedding-ada-002 사용).
- 서버 시작 로그에서 `✅ VECTORSTORE_WEB 로드 완료`, `✅ VECTORSTORE_PDF 로드 완료` 출력 확인.
- 호출 단계 및 결과:
  1. `GET /health` → `200 OK` (`{"status": "ok", "corpus_revision": 1}`)
  2. `POST /sessions` (`{"source": "pdf"}`) → `200 OK`, `session_id` 발급
  3. `POST /rag-query` (질문 1: "출장규정 제12조에서 출장 비용 정산 제출기한은 언제까지인가요?") → `200 OK`, `status="answered"`, `model_calls=4`, `elapsed_ms=5494.97`, `response == answer == output` 일치, 출처 `[S1]`(`스칼라테크 출장규정 제12조 p.5`) 인용 답변 확인
  4. `POST /rag-query` (같은 `session_id`로 후속 질문 2: "그럼 장기출장인 경우에는 어떻게 정산하나요?") → `200 OK`, `status="answered"`, `model_calls=4`, `elapsed_ms=4711.55`, 이전 대화 맥락(출장 비용 정산)을 복원해 출장규정 제12조 p.5(`[S2]`) 근거로 "매월 중간 정산할 수 있습니다..." 답변 확인
  5. `DELETE /sessions/{sid}` → `200 OK` (`{"ended": true}`)
  6. `POST /rag-query` (종료된 `session_id`로 재질의) → `404 Not Found` (`{"detail": "대화를 찾을 수 없습니다."}`)
- 검증 완료 후 임시 기동한 uvicorn 프로세스는 정상 종료해 8001 포트를 비워 두었다.
