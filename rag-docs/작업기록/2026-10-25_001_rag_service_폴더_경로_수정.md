# rag-service 폴더 경로 수정

- 작업일: 2026-10-25 (Asia/Seoul)
- 브랜치: `dev-rag`
- 상태: 수정 및 로컬 검증 완료

## 요청과 목적

사용자가 `soobin_rag`를 `rag-service`로 변경한 뒤 발생한 경로 문제를 확인하고 해결한다.
작업 시작 시 기존 폴더 삭제와 새 폴더의 미추적 상태가 이미 존재했다. 폴더 이동 자체는 사용자의 기존 변경이다.

## 수행 내용 및 변경 파일

- `rag-code-template_ext/rag-service/evaluation/run_evaluation.py`, `run_workflow_smoke.py`: 모듈 루트와 상위 프로젝트 루트를 구분한다. 공용 `.env`와 `faiss_db/pdf`는 상위 프로젝트에서 읽고 모듈 해시는 새 모듈 폴더에서 계산한다.
- `rag-code-template_ext/rag-service/requirements-rag-workflow.txt`: 공용 의존성 포함 경로를 `../requirements-e.txt`로 수정한다.
- `rag-code-template_ext/rag-service/evaluation/README.md`: 새 위치에 맞춰 평가·집계·테스트 명령을 갱신하고 기존 결과를 덮어쓰지 않는 출력 예시를 사용한다.
- `rag-code-template_ext/rag-service/README.md` 신규 작성: 폴더 경계, Windows 실행 명령, Python import 경로, 과거 평가 경로 보존 원칙을 설명한다.
- `RUN.md`, `rag-code-template_ext/프로젝트 구조.md`: 새 모듈 위치와 안내 링크를 추가한다.
- `soobin-docs/LANGCHAIN_LANGGRAPH_RAG_STRATEGY.md`, `RAG_AGENT_USAGE.md`, `RAG_BASELINE_EVALUATION.md`, `RAG_DEVELOPMENT_PLAN.md`, `RAG_ROUTER_WORKFLOW_USAGE.md`, `RAG_TOP_K_COMPARISON.md`, `SESSION_MEMORY_USAGE.md`: 현재 파일 위치·설치·테스트 명령·리포트 링크를 갱신한다.
- 기존 작업 로그와 과거 평가 원본 결과·manifest·코드 해시는 변경하지 않는다. 기존 FastAPI·음성·인증 로직은 변경하지 않는다.

## 검증 결과

- 이전 폴더 이름과 파일 경로, Python import, 의존성 포함 경로, 문서 명령·링크를 정적으로 확인했다.
- Git HEAD의 이동 전 파일과 새 폴더 파일을 비교했다. 기존 파일 중 이번에 수정한 것은 평가 스크립트 2개·평가 README·의존성 파일뿐이며, 나머지 이동 파일과 평가 결과는 동일함을 확인했다.
- 시스템 Python은 3.9만 등록되어 있어, 저장소 밖 임시 가상환경에 제공된 Python 3.12와 검증용 패키지를 준비했다. 설치 완료 전 실행한 최초 테스트에서는 외부 패키지 import 3건이 실패했고 독립 세션 테스트 22개는 통과했다. 설치 완료 후 저장소 루트에서 전체 60개 테스트가 통과했다. 저장소 고정 버전인 OpenAI 1.109.1·LangChain 1.2.7까지 맞춘 후 문서 기준 작업 디렉터리 `rag-code-template_ext`에서 `python -B -m unittest discover -s rag-service/tests`로 재확인하여 60개 모두 통과했다.
- `pip install --dry-run -r rag-code-template_ext/rag-service/requirements-rag-workflow.txt` 성공: 상위 `requirements-e.txt` 포함 및 전체 의존성 해결을 확인했다. 공용 서버 의존성 전체 설치를 수행한 것은 아니다.
- 평가 CLI 3개(`run_evaluation.py`, `run_workflow_smoke.py`, `compare_runs.py`)의 `--help` 로딩 성공.
- 실제 로컬 FAISS 읽기 검증: 저장소 루트·`rag-code-template_ext`·`rag-service`의 세 작업 디렉터리에서 기본 인덱스 경로로 corpus를 임시 폴더에 내보냈다. 세 경우 모두 44개 청크 ID·원문이 기존 corpus와 일치했다. 모든 FAISS 파일의 실행 전후 SHA-256이 같았다.
- 두 평가 스크립트의 모듈 루트·공용 프로젝트 루트와 의존성 포함 파일의 존재를 확인했다. `.env`의 실제 키 유효성은 검증하지 않았다.
- RUN, 새 README, 평가 README와 `soobin-docs` 상위 문서의 로컬 Markdown 링크 대상 모두 존재함을 확인했다. `git diff --check` 통과.
- 외부 LLM·임베딩 API 호출은 수행하지 않았다.

## 남은 작업 및 제약

- 외부 API 실호출·전체 서비스 기동은 수행하지 않았다. 검증은 모의 모델을 사용하는 오프라인 테스트와 실제 로컬 인덱스 읽기로 구분한다.
- Python 3.11 이상이 필요하다. 검증용 환경은 저장소 밖에 생성했으며 기존 실행 환경은 변경하지 않았다.
- `rag-service`는 디렉터리 이름이며 Python 패키지 이름으로 사용하지 않는다. 직접 import 시 해당 디렉터리를 작업 경로 또는 `PYTHONPATH`로 설정해야 한다.
