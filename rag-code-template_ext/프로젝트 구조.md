# RAG 서비스 디렉터리 구조

갱신일: 2026-10-25 (Asia/Seoul)

현재 개발 중인 서비스는 `rag-code-template_ext/rag-service/`다. 공용 환경 설정·패키지 의존성·FAISS 데이터는 상위 `rag-code-template_ext/`에 둔다. 기존 FastAPI 서버와 화면은 별도로 존재하며 새 세션 RAG 서비스에는 아직 연결하지 않았다.

## 디렉터리 구조도

`[준비 위치]`는 현재 파일·폴더가 없고 실행 환경을 구성할 때 생성할 위치다. 캐시 파일은 생략했다. `runs/`와 `comparisons/`는 하위 산출물을 묶어 표시했다.

`rag-service/.env`와 `rag-service/.venv`를 별도로 만들 필요는 없다. 프로젝트용 가상환경은 위 위치가 준비 경로이며, 앞선 테스트에서 사용한 검증용 Python 3.12 환경은 저장소 밖에 있다. `rag-service`는 디렉터리 이름으로 사용하며 Python import는 `from rag_router import RagService`처럼 한다. 직접 호출할 때 이 디렉터리를 작업 디렉터리 또는 `PYTHONPATH`로 설정한다.

## .env 위치와 항목

공용 환경 파일 위치는 **`rag-code-template_ext/.env`**다. 실제 키는 문서나 코드에 넣지 않는다. 아래는 필요한 변수 이름만 보여주는 빈 예시다.

```dotenv
# 기존 PDF 인덱스를 이용한 실제 LLM 평가
OPENAI_API_KEY=

# 기존 서버의 네이버 웹 검색을 사용할 때 추가
NAVER_CLIENT_ID=
NAVER_CLIENT_SECRET=

# 기존 서버의 DB 연결 설정이 필요할 때 추가
# ASYNC_DB_URL=
```

| 항목 | 사용 범위 | 현재 세션 RAG 평가에 필요한가 |
|---|---|---|
| OPENAI_API_KEY | 질문 임베딩·분류·기억 해석·답변 생성·요약 | 필요 |
| NAVER_CLIENT_ID / NAVER_CLIENT_SECRET | 기존 `/upload-topic` 네이버 뉴스 검색 | 기존 PDF 기반 평가에는 불필요 |
| ASYNC_DB_URL | 기존 FastAPI 서버의 비동기 DB 엔진 설정 | 독립 서비스 평가에는 불필요 |

현재 공용 `.env`가 존재하며 OPENAI_API_KEY가 설정되어 있다. 실제 API 인증·모델 접근 가능 여부는 아직 확인하지 않았다. 기존 평가 실행기는 자신의 파일 위치를 기준으로 상위 프로젝트의 `.env`를 로드한다. `RagService` 자체는 `.env`를 읽거나 모델·인덱스를 생성하지 않으므로 직접 사용하는 실행 프로그램이 환경 로드와 의존성 주입을 담당한다. 기존 FastAPI도 서버 파일과 같은 폴더의 `.env`를 읽는다.

## 모듈 연결도

실선은 현재 연결된 경로, 점선은 향후 연결할 경로다. 모델·저장소는 서비스에 주입하며 State에 넣지 않는다.

```mermaid
flowchart TD
    ENV["rag-code-template_ext/.env<br/>로컬 환경 설정"]
    RUNNER["실행 프로그램 / 기존 평가 실행기<br/>환경 로드 · 모델 · 인덱스 준비"]
    MODEL["주입하는 LLM · 임베딩 클라이언트"]
    INDEX["faiss_db/pdf 또는 web<br/>문서 검색 저장소"]
    ROUTER["rag_router.py<br/>RagService · 입력 분류 · 공통 응답"]
    STATE["rag_state.py<br/>request / memory / interpretation<br/>retrieval / result"]
    GRAPH["rag_workflow.py<br/>최근 문맥 해석 · 조건부 요약 조회<br/>검색 · 판단 · 재검색 · 생성"]
    AGENT["rag_agent.py<br/>공통 검색 · 컨텍스트 · 출처 · 생성"]
    SESSION["rag_session.py<br/>세션 실행 직렬화 · 증분 요약"]
    MEMORY["session_memory.py<br/>전체 턴 · 최근 5턴 · 누적 요약<br/>프로세스 메모리에 보관"]
    API["기존 FastAPI /rag-query<br/>현재 기존 RAG 로직 사용"]
    UI["기존 external_index.html"]

    ENV --> RUNNER
    RUNNER --> MODEL
    RUNNER --> INDEX
    RUNNER --> ROUTER
    STATE --> ROUTER
    STATE --> GRAPH
    ROUTER --> GRAPH
    GRAPH --> AGENT
    AGENT --> INDEX
    GRAPH --> MODEL
    AGENT --> MODEL
    ROUTER --> SESSION
    ROUTER --> MEMORY
    GRAPH --> MEMORY
    SESSION --> MEMORY
    SESSION --> MODEL
    UI --> API
    API -.->|"향후 세션 서비스 연결"| ROUTER
```

기존 `run_workflow_smoke.py`는 세션 저장소를 주입하지 않는 호환 호출을 평가한다. 새 세션·자동 요약의 실제 다중 턴 평가 실행기는 아직 없다. 위 연결도는 서비스의 선택적 세션 모드를 포함한 모듈 관계이며, 기존 평가 스크립트가 세션 모드까지 실행한다는 뜻은 아니다.

## 저장 위치와 현재 상태

| 데이터·설정 | 위치 | 유지 범위 |
|---|---|---|
| 환경 설정·API 키 | `rag-code-template_ext/.env` 또는 실행 환경변수 | 로컬 실행 환경 |
| PDF·웹 검색 데이터 | `rag-code-template_ext/faiss_db/` | 디스크 저장 |
| 전체 대화·누적 요약·세션 버전 | `InMemorySessionStore` 내부 메모리 | 해당 프로세스·세션 수명 동안 |
| 요청 State·호출 수·토큰·trace | 요청마다 생성 | 질문 1건 |
| 평가 결과·설정·리포트 | `rag-service/evaluation/runs/`, `comparisons/` | 디스크 저장 |

세션 데이터를 저장하는 별도 디렉터리나 DB는 아직 없다. 메모리 세션은 기본 TTL 30분이며 프로세스를 재시작하면 사라진다. 여러 워커 간 공유·실행 직렬화는 별도 구현이 필요하다.

독립 세션 서비스의 State·기억 조회·완료 턴 저장·증분 요약은 구현했다. 기존 FastAPI·화면 연결, session_facts 도메인 조건 저장, 실제 LLM 다중 턴 평가는 남아 있다. 기존 PDF 업로드의 Q01~Q05 주석은 남아 있지만 청킹·임베딩·저장소 선택·검색·LLM 호출 코드는 구현되어 있다.

기존 FastAPI의 FAISS 상대 경로는 실행 작업 디렉터리를 기준으로 한다. 평가 스크립트의 기본 FAISS 경로는 파일 위치에서 계산하며, CLI로 직접 지정한 상대 경로는 실행 작업 디렉터리를 기준으로 한다.
